# ADR-0001 工程基线与应用标识

- 状态：已接受
- 日期：2026-09-20
- 任务：T01-01
- 依据：`AGENTS.md` §3/§4、`docs/跨平台离线文件互传系统技术方案_V2.1.md` §1.3/§13、`docs/architecture/APP_AND_SERVICE_DESIGN.md` §2

## 背景

NearSend 在本次改动前只有文档与 S0 Python 参考探针，没有任何 Flutter 产品工程。
T01-01 需要建立一个 Android、Windows、iOS 三端齐备的工程骨架，并让版本、协议版本与数据库 schema 版本可追踪。
其中若干取值一旦发布就难以更改（尤其 Android `applicationId` 与 iOS bundle identifier，上架后基本不可逆），因此必须在实现前明确记录并冻结。

## 决策

1. **Flutter 工程位置**：应用工程直接位于仓库根目录（`lib/`、`android/`、`windows/`、`ios/`、`test/`、`pubspec.yaml`），与 `AGENTS.md` §4 的目标目录结构一致。不使用 monorepo 子包结构。
2. **Dart 包名**：`nearsend`。
3. **应用标识**：
   - Android `applicationId` / `namespace`：`com.nearsend.app`
   - iOS bundle identifier：`com.nearsend.app`
   - Flutter `--org`：`com.nearsend`
4. **平台集合**：仅生成 `android`、`windows`、`ios` 三个平台目录。不生成 `linux`、`macos`、`web`——它们不在产品范围内，且会增加与规格无关的构建面。
5. **初始版本号**：`0.1.0+1`（`pubspec.yaml` 的 `version`）。这是开发期版本，不代表可发布版本。
6. **T01-01 不引入第三方运行时依赖**：仅使用 Flutter SDK 自带的 `flutter`、`cupertino_icons` 与开发期的 `flutter_test`、`flutter_lints`。`APP_AND_SERVICE_DESIGN.md` §12 要求新增依赖前记录用途、替代方案、维护状态、许可证、平台支持、是否接触文件/网络/密钥与 S0 结果；T01-01 没有必须引入依赖的需求，因此先引入最少依赖，把依赖决策留给有真实需求的任务。
7. **任务卡存放位置**：`docs/tasks/`（而非 GitHub Issue）。理由见 `docs/tasks/README.md`。
8. **应用显示名**：三端统一显示为 `NearSend`。平台目录中仅允许此类标识类修改。
9. **版本信息注入方式**：构建期通过 `--dart-define` 注入 Git 提交（`NS_GIT_SHA`、`NS_GIT_DIRTY`、`NS_BUILD_CHANNEL`），运行时用 `const String.fromEnvironment` 读取；缺失时显示 `unknown`。不生成需要提交的代码文件，避免「生成的版本文件忘记更新」这一类失真。

## 备选方案与未采用原因

| 方案 | 未采用原因 |
| --- | --- |
| 在根目录直接跑 `flutter create` | 会覆盖仓库既有 `README.md` 与 `.gitignore`，破坏已合并文档。改为在临时目录生成后选择性复制。 |
| `package_info_plus` 读取版本 | 需要引入第三方插件并触发依赖评估流程；`pubspec.yaml` + 常量 + 一致性测试已能满足可追踪性要求。 |
| 生成 `build_info.generated.dart` | 生成文件必须入库或必须依赖构建前置步骤，容易与真实提交不同步；`--dart-define` 更直接。 |
| 用 Git tag / 构建号自动递增 | 发布流水线属于 T10；T01-01 只要求「可追踪」。 |
| Android `applicationId` 采用 `com.nearsend` | 与 iOS bundle id 需要保持一致的工程习惯；统一为 `com.nearsend.app`，为将来同一标识下的其它目标（如 share extension）留出空间。 |

## 影响

- 后续所有任务在同一工程内按 `lib/core`、`lib/features`、`lib/platform` 分层演进。
- `com.nearsend.app` 一旦在 Google Play / App Store 发布即不可更改；如需变更必须在 T10 之前完成并同步本 ADR。
- T01-01 的依赖面保持在 Flutter SDK 内，`pubspec.lock` 需入库以固定解析结果。

## 本 ADR 未冻结（明确留待后续任务）

以下事项在目标设备验证完成前保持「待冻结」，本 ADR 不预设结论：

- Android `minSdk` / `targetSdk`（技术方案建议 Android 10，属建议值）。T01-01 沿用 Flutter 模板默认。
- Windows 最低支持版本（`QUALITY_AND_ACCEPTANCE` 要求以目标设备证据冻结；本机为 Windows 10 22H2）。
- iOS 最低版本、TLS 引擎、端侧 HTTPS 依赖、SQLite 插件与后台 isolate 组合（`SYSTEM_ARCHITECTURE.md` §12）。
- 应用签名材料与发布渠道细节（T10）。
