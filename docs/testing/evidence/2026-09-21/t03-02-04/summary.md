# 运行汇总 t03-02-04：§3 配对端点与会话令牌

任务：[T03-02](../../../../tasks/T03-02.md)　日期：2026-09-21　
范围：**配对的服务端一半**。本运行让「扫码 → 拿到会话令牌 → 用该令牌创建传输」这条
服务端协商在**真实 TLS 连接**上跑通；仍不含 Android、UI 或文件字节传输。

## 1. 交付

- `lib/core/security/pairing_service.dart`：开启配对会话、签发一次性配对令牌、
  处理 `POST /v1/pair`、签发会话访问令牌，并**同时实现 `ControlAuthenticator`**。
- `lib/core/network/control_message.dart`：`ControlRequest` 新增 `peerAddress`。
- `lib/core/security/pairing_token.dart`：抽出 `generateSecureRandomBytes`，
  使「平台 CSPRNG 字节」只有一处定义（会话令牌与配对令牌共用它）。

## 2. 为什么签发方与校验方必须是同一个类

`PairingService` 既发令牌又认令牌，这不是为了省事。**一个签发方产出自己校验方不接受的
令牌，会在两侧的单测里都是绿的**，直到第一次真实配对才失败——而那是在真机上、由用户遇到的。
把两半放在一个类里，"我发的就是我认的"成为一个构造事实。

测试直接从**响应体里取出令牌**、再交给 `authenticate`，正是为了钉住这条：
`pair, then use the token it returned` 这一项不是在断言状态码，而是在**跟着凭证走**。

## 3. `ControlRequest` 为什么需要 `peerAddress`

§3 明写「**每来源**初始限制每分钟 5 次失败，全局每分钟 30 次」。没有对端地址就只能做全局
限流，而只做全局限流意味着**一个坏来源可以耗尽所有人的配额**。地址由传输层提供（它是唯一
持有它的层），随之而来的三条纪律写进了字段注释：

1. 它**不是身份**，从不用于授权——地址在局域网上易伪造、每次重连都变，
   而这正是 §2 把身份与地址分开的原因；
2. `null` 表示传输层没给，此时限流器只能施加全局限制；
3. 调用方**不得**把「没有地址」当成「从未失败过的来源」。

没有地址时所有这样的对端**共用一个桶**，方向是 fail-closed（更容易被限流）。

## 4. 测试结果（15 项新增，全部通过）

单元（`pairing_service_test.dart`，11 项）与真实 TLS 上的闭环
（`pairing_over_transport_test.dart`，4 项）：

| 用例 | 断言 |
| --- | --- |
| QR 载荷 | 指纹/候选/窗口正确，且**能被本项目自己的严格解析器读回** |
| sessionId | 规范**小写 v4 UUID**（版本位 4、RFC 4122 变体位），50 次全过；§4 校验器接受 |
| 正确令牌 | `200`，令牌是 32 字节凭证，且 `authenticate` **接受它** |
| **未知会话 vs 错误令牌** | 两者**同一个** `PAIR_REJECTED`——更细的答案会变成探测会话是否存在的工具 |
| 令牌单次消费 | 第二次 `401` |
| 单调窗口 | 越过 300 秒即失效（与墙上时钟无关） |
| **限流先于令牌检查** | 5 次失败后，**持正确令牌也只得 `429`**，且 `Retry-After > 0`；另一来源不受影响 |
| 重新签发的 QR | **旧会话令牌立即失效**（否则旧二维码的截图仍是可用凭证） |
| 会话令牌过期 | 单调时钟越过 1800 秒即失效 |
| **闭环（真实 TLS）** | 配对 `200` → 用返回的令牌创建传输 `201` → **数据库里确有 1 行任务**；配对本身**不创建任何东西** |
| 猜测会话令牌 | `401 AUTH_EXPIRED`，任务数 0 |
| 未签发的配对令牌 | `401 PAIR_REJECTED`，任务数 0 |
| **无法证明 pin 的客户端** | 根本到不了 `/v1/pair`；且断言的是 `liveSessionCount == 0` 而非"什么都没发生"——**配对令牌仍未消费、仍可能被持有二维码的人使用**，这是比"什么都没发生"更准确的描述 |

## 5. 仍未解决：能力词表

§3 的响应要带 `capabilities:[...]`，而规范**从未枚举任何标识符**。`AGENTS.md` §3 禁止凭偏好
定下未决细节，因此本服务端**宣告空能力集、不做协商**。这是诚实的而不是方便的：
本 build 的两端是同一份代码，它们能达成一致**正是因为没有一方声称任何能力**。
该缺口仍登记在台账 §5，协议冻结前必须由维护者定夺。
