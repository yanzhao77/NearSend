### 2.2 大文件真实落盘

每次独立子进程，4MiB缓冲，每16MiB调用fsync；完整数据真实写入，关闭后重新打开顺序读取并检查整文件SHA-256。不是仅truncate的稀疏文件实验。输入为合成数据，不另外保存20GiB源副本。

| 指标 | 1 GiB | 20 GiB |
| --- | --- | --- |
| 文件字节数 | 1073741824 | 21474836480 |
| 文件系统报告分配字节数 | 1073741824 | 21474840576 |
| 写入＋同步＋生成摘要 | 6.043 秒 | 116.754 秒 |
| 回读＋摘要校验 | 4.566 秒 | 101.605 秒 |
| 峰值RSS | 18816 KiB | 18944 KiB |
| 长度与摘要 | 通过 | 通过 |

20GiB 整文件 SHA-256：`e74f596776b6653cbda56d4bdd968e9bbff1cc14d4c8021adfd31288dd234edf`。

内存从约 18.38 MiB 到 18.50 MiB，支持该探针有界缓冲的判断。文件系统缓存不在此进程RSS口径内，底层持久化语义不由数值证明。20GiB实验初期与很短的小文件/TLS检查有重叠，所以耗时仅作执行记录，不作为严格隔离的速度对比，更不是Wi-Fi或手机性能承诺。

本实验没有网络、SQLite批量checkpoint、移动端URI、导出副本、断电测试，不能等价于20GiB完整产品验收。

## 3. 本轮发现及设计收敛

1. 原方案仅列清单读取接口，缺少大清单的上传过程。草案新增PUT分页及seal，清单完整校验后才请求用户接受。
2. JSON文本直接做摘要存在跨语言不一致风险。固定LFTM1/LFTC1字节编码，明确大端、UUID原始字节、UTF-8长度、数组顺序，提供固定向量。
3. 只在请求开始检查epoch，不能阻止已在途的旧请求继续写入。草案要求恢复与实际写入共用栅栏，撤销并停止旧写入后才建立新世代。
4. 客户端是接收者时，服务端没有其磁盘事实。草案将接收端状态设为权威，服务端checkpoint仅为镜像；不能反向覆盖本地断点。
5. 无客户端推送连接时，服务端发起暂停需要可达路径。新增受认证的control轮询与幂等回执，先停止新数据，再协作完成暂停。
6. Dart官方提供现有Dart Socket升级TLS和最低TLS版本设置，但不能据此证明可直接导入Android原生Network绑定的socket。传输核心是否全Dart仍未冻结。
7. 凭证首次交付可能丢失响应。规范增加安全持久化、幂等重取和receipt；此部分尚未实现/验证。

## 5. 下一轮真机执行单

每条记录：实验ID、应用提交、安装包版本、设备型号、系统/target SDK、无线网卡/驱动、频段、距离、源提供者、目标位置、实际步骤、日志、结果与限制。使用可丢弃测试文件。

### A. Android热点与Windows加入

前置：Android原生调试构建能力、Windows电脑、一台Android真机。原生探针需实现LocalOnlyHotspot回调、接口枚举、监听端口及停止原因日志，本包未包含已编译探针。

1. 关闭Android蜂窝数据和所有上游互联网连接；Windows断开以太网、其他Wi-Fi/VPN。
2. 按系统/target SDK请求对应权限，创建LocalOnlyHotspot，记录实际SSID/接口地址而不在诊断包保留密码。
3. Windows通过系统界面加入；访问探针TLS端口，先传一个带已知摘要的1MiB样本，双向校验。
4. 重建热点、拒绝权限、主动断开、手机锁屏/服务终止，记录状态；恢复后不得沿用旧IP假设。
5. 保持Windows防火墙启用，只开放应用必要范围；错误网络配置应有可诊断提示。

通过门槛：断开上游仍实际收发；错误配置明确失败；重建后重新发现/认证，不硬编码网关。记录支持机型，不泛化到全部Android。

### B. Android加入者网络绑定及Dart衔接

前置：第二台可建热点设备或受控测试AP；Android同时存在蜂窝/其他默认网络。

1. WifiNetworkSpecifier申请目标网络，处理用户确认、onAvailable/onUnavailable/onLost。
2. 使用返回Network的绑定能力建立实际连接，分别测试原生TLS路径和拟用Dart适配路径。
3. 记录网络句柄与连接接口/地址，在其他默认网络存在时仍能传已知摘要样本。
4. 绑定网络丢失后必须失败并进入重连；不能悄悄从其他路由继续向同IP发送凭证。

通过门槛：绑定和TLS均工作，明确字节流跨原生边界的复制/缓冲；若纯Dart接入不成立，则选择经过验证的原生传输适配，不强行拼接未经验证的fd。

### C. 文件来源与持久化

分别选择本地文件、外接存储可用文件、文档提供者、未下载云端占位文件。测试初读、seek、应用强退/重启重开、授权撤销、源文件修改。Android调用适合来源的持久URI授权流程；不可重开/不可seek时才暂存并检查空间。离线云文件不可读取时明确阻断。

接收端在真实持久目录重复四个崩溃窗口；应用升级迁移与设备重启另测。执行导出不足空间、目标不可用和导出回执丢失，确认不重复生成用户文件。

### D. iOS早期探针

在macOS/Xcode签名的iPhone构建中验证本地网络授权拒绝/允许、Bonjour或扫码直连、加入Android热点、同一TLS pin正反例。选择本地可读取大文件，测试访问授权生命周期、锁屏/切后台/回前台恢复。来源不可持久重开时记录暂存策略。当前阶段不承诺后台持续运行。

### E. 真机20GiB及小文件

先通过小样本，再跑20GiB：分别记录准备扫描、纯传输、校验、导出与恢复复核；30%断网、强退/重启分别做独立用例。记录实际补传块集合，而不仅看进度条。

小文件分别测1,000×4KiB、10,000×4KiB、空文件及混合集合；增加一个文件失败和同名冲突。检查完成数量、逐文件哈希、峰值内存/句柄、数据库大小和界面可操作性。10,001文件在创建前拒绝。

## 6. 架构冻结门槛与紧接着的工作

优先补齐Android/Windows的开发环境和真机，执行A/B/C；iOS并行安排早期探针，不等主产品完成后才检查。这里的“并行”是里程碑排程，不代表本轮调用了多代理或已在其他设备执行。

在目标端明确：Flutter/Dart版本、各最低OS、TLS引擎、Android网络绑定适配、StorageAdapter能力及安全存储方案。记录依赖版本和失败设备；所有关键实验有证据后，将协议draft1升为冻结版本，并进入T01—T03工程闭环。

当前不能承诺跨平台20GiB传输成功、自动热点普遍兼容、断电零丢失或App已可安装。无需改变产品方向；需要目标环境兑现其平台接口。
