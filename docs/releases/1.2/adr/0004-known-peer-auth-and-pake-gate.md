# ADR 0004：已知设备挑战认证与 PAKE 门禁

状态：已接受（已知设备认证）；受阻（首次短码 PAKE）

日期：2026-09-24

## 背景

雷达需要区分“发现了一个广播”和“已授权设备刚刚证明自己在线并愿意连接”。同时，计划要求首次
短码配对使用标准 PAKE，不能把可穷举短码直接发送、散列比较或拿来加密热点密码。

## 决策

已配对设备使用长期 P-256 身份对 32 字节新鲜挑战签名。规范 transcript 同时绑定 verifier/prover
角色、协议版本、事务 UUID、双方 device ID、挑战、就绪位和当前 TLS leaf 指纹。签名固定为
64 字节 low-S `r || s`，挑战与就绪证明均在 30 秒后失效。

只有 SQLite 中仍为 `authorized` 且公钥精确匹配的记录可以通过。验证成功才能更新
`last_verified_at` 和该长期身份连续性下的 TLS pin；失败会消费挑战。双方必须独立验证对端，BLE
角色、热点角色和文件发送方向互不推导。

消息格式与 transcript 见 [`known-peer-auth-v1.md`](../../../protocol/known-peer-auth-v1.md)。

## PAKE 候选结论

| 候选 | 审查结果 | 决定 |
|---|---|---|
| `spake2plus 1.0.2` | MIT；含 RFC 9383 Appendix C 向量；只声明 Linux/macOS，依赖 OpenSSL 3 FFI，无 Android/Windows/iOS 支持 | 不接入 |
| `dsrp 0.5.5` | Apache-2.0；纯 Dart SRP-6a；0.x、未审计，发布包无测试目录，要求调用方自选生产 safe prime | 不接入 |

没有合格候选时保持首次短码路径受阻。不得以自研协议填补计划复选框。现有严格二维码载荷、TLS pin
和一次性高熵令牌仍可用于首次配对，但不宣称完成雷达短码流程。

## 结果

- 历史设备可在不信任广告和地址的前提下取得短期在线/就绪证明。
- TLS 证书轮换只有在长期身份签名覆盖新 pin 后才可连续绑定。
- 撤销、重放、篡改、角色反射、身份替换和待处理资源耗尽有自动化负例。
- V12-07 仍是部分完成；在成熟 PAKE 依赖及跨平台向量验证完成前，首次短码配对不可交付。
