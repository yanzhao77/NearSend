# 离线大文件互传协议 v1.0-draft1

日期：2026-09-20。依据：技术方案 V2.1。状态：S0 可实现草案；尚未通过 Dart/Kotlin/Swift/Windows 独立互操作测试，不标记为正式冻结。

本规范收敛传输语义和编码，不修改既定产品定位。Python 参考代码仅验证部分底层不变量，不是 Flutter 产品、完整网络服务或生产安全库。

## 1. 范围、角色与不变量

- 网络：已有局域网或已建立热点，不依赖互联网、账号、公共 CA 在线查询、云服务。
- 连接角色：HTTPS server/client 在任务生命周期内固定。网络创建者与发送者独立。
- 文件方向：client_to_server 使用 PUT；server_to_client 使用 GET。每任务只有一种文件方向。
- 接收方拥有本地断点、checkpointSeq 和 leaseEpoch 的唯一裁决权；服务端如果是发送者，只保存镜像。
- 完成必须同时满足全部块已提交、整文件长度/哈希正确、所需导出已确认。网络 100% 不等于完成。
- 每任务串行恢复；每文件只有一个有效写入者。认证、清单冻结、接收确认完成前不处理任何文件字节。
- UI 的 receivedBytes/writtenBytes 不可作为恢复依据。重启后先复核已提交块；损坏会导致 committedBytes 合理下降。

## 2. 传输层和身份

HTTPS/1.1，TLS 最低 1.3。协商不到最低版本立即终止，不降级明文。单任务首版一条数据连接、一条控制连接，不启用 HTTP pipeline、压缩、HTTP Range 或 TLS 0-RTT。控制接口可在数据连接背压时继续工作。

首次信任来源是用户直接扫描/输入的完整配对信息。fingerprint = SHA-256(服务端叶证书完整 DER)，小写 64 位十六进制。不是 PEM 文本摘要，也不是公钥 SPKI 摘要。首次认证和每次重连都验证；证书轮换触发重新配对。发现广播仅用于定位。

采用每连接隔离的信任上下文；必须在发送令牌、HTTP 请求及文件内容之前完成指纹比对。即使证书受系统 CA 信任也必须比对 pin，不能只在“不可信证书回调”中比对。比较失败关闭连接，不跟随 HTTP 重定向，不将凭证发送到新的 origin。离线 pin 模式的证书日期与主机名策略须在目标引擎原型中明确；信任判定以直接获取的精确 pin 和 TLS 私钥持有证明为核心，不因离线时钟错误改成接受任意证书。

服务端私钥、客户端任务恢复凭证使用平台安全存储。服务端仅保存恢复密钥验证摘要；受限完成查询使用不同的凭证。TLS key log 不进入产品构建。

### 2.1 mDNS 发现扩展（1.2 草案）

mDNS/DNS-SD 服务类型为 `_nearsend._tcp`。服务实例名称仅使用 `NearSend-` 加短期实例 UUID 的
前 8 位，不使用名称或地址作为身份。TXT 字段固定为 `maj`、`min`、`iid`、`caps`：版本使用规范
非负十进制，`iid` 为当前短期会话 UUID，`caps` 当前为 `discovery.mdns.v1`。

发现记录是未认证输入。TXT 不得携带长期设备 ID、公钥、TLS 指纹、配对/访问令牌、热点凭据、
文件或路径信息。实现最多接受 16 个能力和 16 个已解析地址，过滤 loopback、unspecified、
multicast 和保留地址；服务丢失立即移除该来源。发现到地址只表示候选，后续仍须完成身份认证、
TLS pin/端点绑定和任务授权。mDNS 不可用或网络隔离时不能降级安全校验，也不能把历史记录显示为在线。

## 3. QR 与会话

二维码内容为 UTF-8 JSON（不带 URL 自动跳转），最大 4096 字节，必填字段：

| 字段 | 类型/约束 |
| --- | --- |
| kind | 固定 lft-pair |
| protocolMajor / protocolMinor | JSON 整数 1 / 0 |
| serverFingerprint | 64 位小写十六进制 |
| sessionId | 规范小写 UUID |
| candidates | 最多 8 个 {host:string,port:integer}；port 1—65535 |
| pairToken | 32 随机字节的 base64url 无填充编码 |
| expiresInSeconds | 提示值 300；以服务端状态为准 |

host 是明确本地接口地址，处理 IPv6 scope 时用结构化地址解析；不允许凭证、路径、查询参数混入 host。候选地址选择不能绕过 pin。热点 SSID/密码可在独立连接引导中显示，尚未连接时由用户授权加入；二维码认证本身不声称能自动完成系统 Wi-Fi 配置。

POST /v1/pair 请求 {requestId,sessionId,pairToken,clientLabel,protocolMajor,protocolMinor}。clientLabel UTF-8 最多 128 字节，仅展示，不是身份。成功 200 返回 {sessionAccessToken,expiresInSeconds:1800,protocolMajor:1,protocolMinor:0,capabilities:[...]}。令牌不放 URL。访问令牌为 32 字节随机值，经 Authorization: Bearer 发送。

配对令牌 300 秒内单次消费，以服务端单调计时判定；服务重启时未消费的配对令牌全部失效。配对响应丢失时不恢复已消费配对令牌，重新生成 QR；既有已授权任务走恢复凭证。失败统一 PAIR_REJECTED，避免暴露令牌存在性。每来源初始限制每分钟 5 次失败，全局每分钟 30 次失败，返回 429，限流不替代随机熵。

会话认证只允许提议/查看该会话下的待授权任务，不能读取任意文件。用户接受任务后服务端生成该任务的客户端恢复密钥并持久化验证材料；通过受认证的 /authorization 交付，客户端安全保存后发送 receipt。未收到 receipt 时保留同一待交付密钥在安全存储中的密文，以支持幂等重取；确认后移除可恢复原文。禁止每次重试生成不同密钥。初次授权交付完成后也调用 /resume 建立首个有效任务访问令牌和写入世代，再进入 READY；READY 不意味着可以绕过世代检查。会话在凭证交付前丢失则重新配对并由用户重新授权关联任务。

## 4. JSON、整数与统一约束

控制体 application/json; charset=utf-8，单请求/响应最大 1 MiB；JSON 深度最多 16，重复对象键、NaN/Infinity、非法 Unicode 拒绝。内容按 UTF-8 解释，不接受 BOM。v1.0 对定义以外的字段拒绝 INVALID_FIELD，不静默丢弃。

字节数、块编号、chunkCount、leaseEpoch、checkpointSeq：十进制字符串，正则 0|[1-9][0-9]{0,18}，范围 0..2^63-1，不允许符号、指数和前导零。UUID 为规范小写带连字符字符串；实际标识使用随机 UUID，不凭任务 ID 授权。

协议版本、chunkSizeBytes、length、fileCount、pageLimit 使用 JSON 整数（不能是 boolean），范围按具体字段限制。文件大小总和不得溢出有符号 64 位。

SHA-256 为 64 位小写十六进制。密钥编码统一 base64url 无 '=' 填充，32 字节对应 43 字符；解码后重新编码必须相同。

## 5. 冻结清单与摘要编码

顶层字段恰好为 protocolMajor、protocolMinor、transferId、files。files 数组按用户确认时的逻辑顺序固定；字段键的 JSON 排序和空白不影响摘要，数组重排会影响摘要。

每项字段恰好为 fileId、relativePath、sizeBytes、chunkSizeBytes、chunkCount、fileSha256、chunkManifestDigest。chunkSizeBytes 在 v1.0 固定 4194304。chunkCount = ceil(sizeBytes / 4194304)，以十进制字符串编码。0 字节文件有 0 块，整文件摘要使用 SHA-256(empty)。最后一块长度由文件大小推导。

与 V2 示例的收敛：protocolVersion 拆为 major/minor；chunkCount 和块索引改为十进制字符串；manifestDigest 是外层提议/响应字段，不参与清单自身摘要。尚无已发布客户端，因此不需要兼容旧示例格式。

首版每任务 1—10,000 个文件，最多 1,048,576 个块；超过数量在接收字节前拒绝 RESOURCE_LIMIT。此限制控制元数据规模，并不宣称对应总容量经过验收。

### 5.1 文件名

发送端生成 NFC 规范化相对路径，接收端遇到非 NFC 拒绝，不默默改动参与摘要的名称。UTF-8 编码长度 1—1024 字节。分隔符只允许 '/'；拒绝空段、'.'、'..'、绝对路径、反斜线、冒号、控制字符、Windows 非法字符、保留名、末尾空格/点。重复显示路径允许，但必须不同 fileId，接收确认时为目标分配不同安全名称。

relativePath 是元数据，不直接拼接成可写路径。首版不重建递归目录，默认使用经安全映射的末段文件名；冲突自动改名并持久化 fileId→目标引用。平台额外命名限制、大小写冲突、Unicode 冲突、符号链接/reparse point 由存储适配层处理。参考 path_bytes 只验证词法，不验证句柄级防逃逸。

### 5.2 清单摘要 LFTM1

所有整数为固定长度、无符号、大端序二进制；其合法范围仍限制为本规范范围。字符串长度按 UTF-8 字节数，UUID 按标准网络序 16 字节。

按以下顺序串联：

1. ASCII `LFTM1` 加一个 0 字节（共 6 字节）。
2. major:u16、minor:u16、transferId:16 bytes、fileCount:u32。
3. 依 files 顺序，每项串联：fileId:16 bytes；pathByteLength:u32；pathUTF8；size:u64；chunkSize:u32；chunkCount:u64；fileSha256:32 raw bytes；chunkManifestDigest:32 raw bytes。
4. manifestDigest = SHA-256(以上完整二进制序列)。

只定义摘要的字节编码，线上控制消息仍为 JSON。不能直接 hash JSON 文本，也不能用语言默认序列化或本机字节序。

### 5.3 块清单摘要 LFTC1

每条块记录恰好包含 index:string、length:integer、sha256:string。块从 0 连续升序，length 必须等于由 size 推导的长度。

摘要输入 = ASCII `LFTC1` + 0 字节 + chunkCount:u64 + 每块(index:u64 + length:u32 + sha256:32 raw bytes)。空文件仍包含前缀和 0 计数。chunkManifestDigest = SHA-256(该输入)。

整文件摘要始终对原始文件字节顺序计算，不对块摘要拼接计算。[vectors-v1.json](vectors-v1.json) 提供空文件、中文路径 abc 内容、4 MiB＋3 字节尾块的完整预期编码和摘要。该向量由 Python 参考实现生成，需另用 Dart/原生实现独立比对后才能作为跨语言通过证据。

## 6. 提议、分页和接收确认

解决 V2 的大清单上传缺口：新增 PUT 清单分页与 seal；避免 10,000 文件清单超出 1 MiB 控制体。

客户端为发送者：POST /transfers 创建 staging 任务；分批 PUT 文件页和块页；POST /seal；服务端验证所有页与总摘要后展示接收确认。

服务端为发送者：用户本地创建 staging 任务并完成同样校验；GET /offers 仅向已配对会话列出指定给该会话的任务描述；客户端 GET 清单页后验证 seal 和摘要，显示接收确认。未知会话不能枚举 offers。

文件页最大 128 项，块页最大 1024 项，并同时受 1 MiB 上限约束。页结构 {manifestDigest,kind,fileId?,startIndex,items}；startIndex 是十进制字符串，files 页不得带 fileId，chunks 页必须带 fileId。每页覆盖连续索引区间，重传相同页返回成功，重叠区间内容不一致拒绝；保存时按条目索引去重，不能用重复页增加累计数量。

缺页、重复 fileId、块数量/长度错误、总摘要不一致时 seal 失败，不能进入 WAITING_ACCEPT。seal 后页不可修改。首次收到内容后 30 分钟 staging 未完成则清理并撤销该提议；该超时只约束**未 seal** 的 staging，不影响已经冻结的任务。生产实现必须把 staging 页及 seal 结果持久化到 SQLite；首版演示可使用有界内存实现，但不得宣称支持服务端重启恢复。seal、取消或终态失败后释放 registry；可修复的 seal 校验失败保留页面供补传。registry 必须设置并发任务和内存/记录上限，超限返回 RESOURCE_LIMIT。

只有接收方能接受：接收者是 server 时走本地动作；接收者是 client 时 POST /decision。批准清单摘要、保存位置以及空间估算一起持久化；路径或身份变化需要重新确认。任务读写权限范围绑定 transferId、manifestDigest、方向和已批准文件。

接收方在接受前可以使用与任务绑定的会话身份分页读取 files 清单元数据，用于展示并持久化本地输出计划；未绑定会话仍统一返回 404。该读取不交付任务访问令牌，也不开放 chunk 数据。输出计划至少记录 transferId、fileId、冻结原始路径、本地保存名、目标位置引用、冲突策略和导出状态。用户修改保存名只改变本地输出映射，不改变冻结清单、manifestDigest、fileId、分块摘要或恢复语义；输出计划不发送给对端。

## 7. API 契约（/v1 前缀）

所有 ID 参数须先解析校验。除 pair 外均需要有效 Bearer，resume 使用 taskResumeSecret 专用请求体；初次 resume 无须旧会话令牌。任务查询对无权限资源统一 404。

| 方法与路径 | 关键请求字段 | 成功响应及语义 |
| --- | --- | --- |
| POST /pair | 见第 3 节 | 200 会话凭证 |
| GET /offers?cursor=... | 会话身份；游标为返回的不透明值 | 200 {offers:[{transferId,manifestDigest,fileCount,totalBytes}],nextCursor:null或string}；每页最多128项 |
| POST /transfers | requestId,transferId,manifestDigest,fileCount,totalBytes,direction | 201 {transferId,state:STAGING}；客户端仅可提议 client_to_server；服务端发送由本地创建 |
| PUT /transfers/{id}/manifest | 页结构，Authorization | 200 {stored:true}，仅客户端发送者可写 staging |
| GET /transfers/{id}/manifest?kind=files或chunks&fileId=...&startIndex=...&limit=... | 与已授权任务绑定 | 200 对应页及 nextIndex:null或十进制字符串；返回 manifestDigest |
| POST /transfers/{id}/seal | requestId,manifestDigest | 200 {state:WAITING_ACCEPT}，摘要失败422 |
| POST /transfers/{id}/decision | requestId,manifestDigest,decision:accept或reject | 200 {state}；仅客户端接收者调用；server 接收者本地决定 |
| GET /transfers/{id}/authorization | 已授权会话 | 200 {taskResumeSecret,completionQuerySecret}；限批准任务，缓存禁止 |
| POST /transfers/{id}/authorization/receipt | requestId | 200 {stored:true}，确认客户端已安全保存凭证 |
| POST /transfers/{id}/resume | requestId,manifestDigest,taskResumeSecret,receiverState? | 202 {state:CHECKING_RESUME} 或 200 {taskAccessToken,expiresInSeconds:1800,leaseEpoch,checkpointSeq,state}；client 接收时必带已恢复的 receiverState |
| GET /transfers/{id}/status?fileId=...&startIndex=...&limit=... | 会话、任务令牌或受限完成查询令牌 | 200 状态及一致快照分页；见第 9 节 |
| PUT /transfers/{id}/files/{fid}/chunks/{index} | 二进制体、长度、lease、manifest headers | 202 verified_pending 或 200 committed；仅 client_to_server |
| GET /transfers/{id}/files/{fid}/chunks/{index} | taskAccessToken、lease、manifest headers | 200 二进制块；仅 server_to_client，下载成功不代表接收端持久化 |
| POST /transfers/{id}/checkpoint | requestId,manifestDigest,leaseEpoch,checkpointSeq,committedBytes | 200 {mirrored:true}；仅 client 接收者汇报，server 只更新显示镜像 |
| POST /transfers/{id}/pause | requestId,leaseEpoch | 202 {state:PAUSING} 或 200 {state:PAUSED} |
| POST /transfers/{id}/complete | requestId,leaseEpoch,fileId,result:request_verify或saved,fileSha256? | 202 校验处理中或200已保存；角色语义见第10节 |
| POST /transfers/{id}/cancel | requestId | 200 {state:CANCELLED}，撤销授权 |
| GET /transfers/{id}/control?afterSeq=... | taskAccessToken；afterSeq 十进制字符串 | 200 {commands:[{seq,type}],lastSeq}；type=pause或cancel，首版轮询间隔1秒 |
| POST /transfers/{id}/control/receipt | requestId,lastAppliedSeq | 200 {stored:true}；客户端确认已处理命令 |

未知字段拒绝；错误体 {code,message,retryable,requestId?}，message 不含密钥或完整本地路径。成功体中的 token 字段只出现在专门授权/恢复响应，所有控制响应 Cache-Control: no-store。

control 解决 server 是发送者而 HTTP client 是接收者时的主动暂停通知：服务端先停止提供新数据，客户端轮询命令并完成 checkpoint，再确认；命令重复按 seq 幂等。同样的本地取消必须立即停止本端工作，不依赖对端在线。离线对端下次恢复被拒绝；取消清理的远端即时性不保证。

## 8. 块请求和持久化确认

块索引从 URL 十进制解析，offset = index × 4194304，乘法先检查范围，不能接受客户端任意 offset。要求 Content-Type: application/octet-stream、单一 Content-Length；不支持 Transfer-Encoding，不允许压缩，拒绝 Content-Length/Transfer-Encoding 同时出现。body 长度必须等于该块预期长度，末尾额外数据拒绝并关闭连接。

任务相关请求头：Authorization: Bearer taskAccessToken、X-LFT-Lease-Epoch、X-LFT-Manifest-Digest。服务端 GET 返回 Content-Length 和 X-LFT-Chunk-SHA256；接收者仍以冻结清单为权威。

PUT 返回 {index,state:verified_pending或committed,leaseEpoch,checkpointSeq}。verified_pending 只证明本次块长度/摘要正确，不可释放持久化确认跟踪。重复已提交块必须校验世代、长度和内容；内容冲突返回 CHUNK_HASH_MISMATCH，不可因“已有块”就无条件成功。

写入顺序：认证和授权→文件锁→再次检查 epoch→写入并验证长度/块摘要→受控待提交队列→syncData→SQLite 事务提交块标志和 checkpointSeq→发布 committed。写入途中失败保留未提交状态，不返回 committed。

每文件串行写入；恢复获得相同写入栅栏，先撤销旧会话，等待旧写入停止，再分配新 epoch，校验已有数据。只在请求入口检查 epoch 不够，旧请求不得在新世代建立后继续写入。

最多 16 MiB 待持久化有效数据，缓冲有界；每 16 MiB 或 1 秒 checkpoint，暂停/文件结尾强制提交。参考 storage_probe 为降低实验复杂度，每块单独 fsync 和 DB 提交，不验证生产批量窗口和背压。

## 9. 恢复、幂等与状态分页

taskResumeSecret 由原服务端验证，绑定原任务和方向；原服务端身份 pin 必须先通过。成功换发 taskAccessToken。恢复密钥失效或身份更换，重新配对并请用户批准关联临时文件，不直接信任新设备。

server 接收者：/resume 驱动本地接收恢复，完成后返回新 epoch。client 接收者：先在本地持久化新 epoch、复核断点，再提交 receiverState={leaseEpoch,checkpointSeq,committedBytes}；发送者验证不回退并更新镜像。**恢复只以接收端已经持久化的 committed 块与 checkpoint 为准**；发送端记录始终是镜像，不得反向覆盖接收端本地事实。缺失块来自客户端本地，客户端按缺失块 GET，不需要向发送者提交巨大的缺失区间表。

requestId 为规范 UUID，作用域是同一任务＋操作＋当前恢复凭证。每次操作持久化请求摘要和结果；相同 ID 不同参数拒绝 REQUEST_ID_CONFLICT。同一恢复 requestId 重试不得再次递增 epoch；若后续恢复已创建更高 epoch，则旧 requestId 返回 STALE_RESUME_REQUEST，不返回可写的旧令牌。当前 requestId 尚在处理中返回202，客户端退避轮询或同ID重试，不启动新的恢复。

状态体：{transferId,manifestDigest,state,leaseEpoch,checkpointSeq,committedBytes,fileId?,missingChunkRanges?,snapshotId?,nextCursor?}。missingChunkRanges 是两端包含的十进制字符串对，递增、不重叠、不越界；每页最多1024区间。服务端接收时提供权威快照；服务端发送时响应明确标记 authority:sender_mirror，不能据此覆盖客户端本地事实。受限完成凭证只返回终态、文件ID及摘要确认，不返回路径、清单、密钥或文件数据。

缺失区间分页固定在同一个 snapshotId，附 epoch/seq；存储状态变化而旧快照已释放时返回409 SNAPSHOT_EXPIRED，从第一页重读，不能把不同世代页面拼接。缺失表可从冻结快照派生，也可由接收者直接本地调度。

## 10. 状态机、完成和清理

初始 STAGING→WAITING_ACCEPT→READY→TRANSFERRING→VERIFYING→EXPORTING→COMPLETED。准备文件是发送端本地 PREPARING，未冻结前不开始网络数据传输。协议状态名与数据库状态名允许不同，但实现必须通过单一转换层编解码；业务代码不得手写数据库状态字符串。

TRANSFERRING→PAUSING→PAUSED；网络断开→INTERRUPTED；恢复→CHECKING_RESUME→READY/TRANSFERRING；缺权限/空间/源变化→BLOCKED；不可恢复协议错误→FAILED。队列处理结束但有未完成项→PARTIALLY_COMPLETED。所有状态可本地取消→CANCELLED，已完成任务的清理是另一操作。

server 接收时，client 的 complete(result=request_verify) 只是请求触发终检；server 本地验证、保存完成才进入 COMPLETED。client 接收时，只有本地终检和导出确认后才能 complete(result=saved,fileSha256=冻结摘要)，server 将其记录为对端报告的完成，不能声称自己独立读取了对端磁盘。

暂停整个任务队列，默认保留热点和连接；暂停中断块可以重传，checkpoint 完成前不显示已暂停。取消清除未完成暂存并撤销恢复授权，已经导出的文件保留。完成状态凭证保留7天，任务未完成默认7天可延期；活动任务不按保留期限删除。

导出结果未知时禁止盲目生成第二份文件：查询原目标引用、大小和可用校验信息，无法确定则请用户确认。确认已保存后释放应用内副本。空文件仍需创建、同步、导出并记录完成，没有网络块请求。

## 11. 错误、超时与资源限制

| HTTP | code 示例 | 行为 |
| --- | --- | --- |
| 400 | INVALID_FIELD / INVALID_DECIMAL / INVALID_PATH | 修正请求，不自动原样重试 |
| 401 | PAIR_REJECTED / AUTH_EXPIRED / RESUME_REJECTED | 配对或恢复，不向新身份发旧凭证 |
| 403 | DIRECTION_FORBIDDEN | 终止错误操作 |
| 404 | NOT_FOUND | 对未知/未授权任务统一返回 |
| 409 | STALE_LEASE / REQUEST_ID_CONFLICT / SNAPSHOT_EXPIRED / INVALID_STATE | 查询状态；旧写入者停止 |
| 410 | TASK_EXPIRED / TASK_CANCELLED | 不自动建立重复任务 |
| 413 | RESOURCE_LIMIT / BODY_TOO_LARGE | 缩小任务或正确分页 |
| 422 | MANIFEST_MISMATCH / CHUNK_HASH_MISMATCH / SOURCE_CHANGED | 阻断或按正确来源修复，不无限重试 |
| 429 | RATE_LIMITED | 按Retry-After（秒）退避 |
| 500 | STORAGE_SYNC_FAILED / DB_COMMIT_FAILED | 不确认提交，保留可恢复状态 |
| 507 | SPACE_INSUFFICIENT | 用户清理/换位置后重试 |

连接/TLS 建立超时10秒；普通控制请求30秒；块传输按30秒无字节进展超时，不按整个20GiB总时长超时。用户确认不占用一个长期 HTTP 请求，返回等待状态。重连1/2/4/8秒递增加抖动，上限30秒，前台约2分钟后等待用户。

任务同一时间最多一条数据请求在途（首版），另有控制连接。大清单和队列状态不得完整复制到每次UI刷新；哈希与磁盘操作移出UI isolate。文件保留、数据库迁移、权限恢复沿用 V2.1。

## 12. 需要目标端验证后才能冻结的事项

- Dart TLS1.3 最低版本设置、握手后对所有证书强制 pin；错误证书不能泄露任何 HTTP 请求。
- Android Network socket 绑定如何安全衔接 Dart 或原生 TLS；不能由 SecureSocket.secure 存在就推导能导入原生 fd。
- 各存储后端 syncData 的实际语义及目录项同步/原子提交能力。
- 安全存储的凭证交付重试、重启重开与清除行为。
- iOS 局域网许可、文件访问期限、前后台恢复；Windows 防火墙和无摄像头连接。
- 独立实现向量一致性、完整API鉴权/幂等/限流、批量checkpoint/背压及真实双端断网测试。

参考实现未包含以上完整能力，不可直接发布。

## 13. 依据

平台事实和项目协议选择分开：本规范的字节编码、路由、超时和资源限制是项目设计决定。

- [Android LocalOnlyHotspot](https://developer.android.com/develop/connectivity/wifi/localonlyhotspot)：本地热点及权限。
- [Android Wi-Fi Network Request API](https://developer.android.com/develop/connectivity/wifi/wifi-bootstrap)：系统连接确认和非互联网连接。
- [Android Network](https://developer.android.com/reference/android/net/Network)：socket 网络绑定接口。
- [Android SAF](https://developer.android.com/training/data-storage/shared/documents-files)：URI 与文档提供者访问。
- [Dart SecureSocket.secure](https://api.dart.dev/dart-io/SecureSocket/secure.html)：现有 Dart socket 上建立 TLS；不是原生句柄互通保证。
- [Dart minimumTlsProtocolVersion](https://api.dart.dev/dart-io/SecurityContext/minimumTlsProtocolVersion.html)：最低 TLS 版本设置，默认不能当作已强制1.3。
- [SQLite synchronous](https://sqlite.org/pragma.html#pragma_synchronous)：WAL/FULL 相关同步语义，依赖底层存储兑现。
- [TLS 1.3 RFC 8446](https://www.rfc-editor.org/rfc/rfc8446)：标准TLS；不自行发明加密握手。
