## 目标

让「用户扫码 → 确认对端身份 → 才交出一把只能消费一次的令牌」这条链路有一个
**不依赖调用方纪律**的实现：令牌在指纹比对成功之前**取不到**，而不是「文档说不要提前发」。

同时把 QR 载荷的解析做成严格解析：它是客户端从不受信来源读到的第一个东西，
并且决定「连到哪里」和「信任谁」。

## 范围内

- **配对载荷（§3/§4）**：`kind`、协议版本、`serverFingerprint`、`sessionId`、
  `candidates`（≤8，`host` 必须是裸地址、`port` 1–65535）、`pairToken`（base64url 无填充 32 字节）、
  `expiresInSeconds`；UTF-8 ≤ 4096 字节；**未定义字段一律拒绝**（§4）。
- **base64url 规范编码（§4）**：无填充、URL 字母表、**解码后重新编码必须相同**。
- **指纹计算（§2）**：`SHA-256(叶证书完整 DER)` 小写 64 hex。
  **不是** PEM 文本摘要，**不是** SPKI 摘要。
- **每连接信任上下文（§2）**：比对成功前不得释放令牌；比对失败关闭连接且不得复用；
  未使用前 `abandon()` 可关闭。
- **安全负例**：错误指纹、大写指纹、非规范 base64url、带 scheme/凭证/路径/查询的 host、
  保留字段、超限载荷等。

## 接口与不变量

- **令牌在比对成功之前取不到。** 这不是文档约定：`PairingHandshake` 只通过一个 getter
  暴露令牌，且该 getter 在未比对或已关闭时抛 `PAIR_REJECTED`。调用方没有「顺序」需要记住。
- **比对失败即关闭连接**（§2），且**不得在同一上下文上重新协商**——
  在对端身份校验已失败的连接上重试，正是重试循环变成攻击的方式。
- **每连接隔离**：一个连接的失败不泄漏到另一个连接。
- **不够用的证书编码也关闭连接**：不变量是「除非比对显式返回 trusted，否则关闭」。
- **指纹按 DER 计算**：参数类型是字节而非字符串，因此没有「传 PEM」的重载。
- **比较不是常数时间**：指纹发布在用户扫描的二维码里，不是秘密，时序信道不泄漏任何
  攻击者尚未拥有的东西；手写常数时间比较等于为不存在的问题发明密码学代码（`AGENTS.md` §5）。
- **候选地址选择不得绕过 pin**（§3）：本任务只做词法校验，可达性判定属 B02。

## 验收条件

- [x] QR 载荷严格解析：必填字段、类型、范围、UTF-8 上限；未定义字段被拒绝。
- [x] `serverFingerprint` 必须是 64 位**小写**十六进制；大写、长度不符、非 hex、base64 形状均被拒绝。
- [x] `pairToken` 必须是 32 字节的**规范**无填充 base64url；带填充、长度不符、非规范写法、标准字母表均被拒绝。
- [x] `candidates`：空列表、超过 8 个、端口 0/65536、端口为字符串被拒绝。
- [x] `host` 带 scheme / 凭证 / 路径 / 查询 / 空白 / 括号被拒绝；IPv4 越界与前置零被拒绝；主机名被拒绝。
- [x] 指纹是 SHA-256(DER)，且**有测试证明它不等于 PEM 文本摘要**、也不等于对 DER 一部分的摘要。
- [x] 比对成功前读取令牌抛 `PAIR_REJECTED`；成功后可用。
- [x] 比对失败关闭上下文，令牌**永久**不可用，且同一上下文不得重新协商。
- [x] 一个连接的失败不影响另一个连接（每连接隔离）。
- [x] `dart format`、`flutter analyze`、`flutter test` 通过；CI 四个作业通过。
- [ ] 目标端网络绑定与候选地址可达性（**阻塞于 B02**）。

## 本次结果

### `t03-01-01`：配对载荷与「pin 先于令牌」的信任上下文

已实现 `pairing_payload.dart`、`pairing_trust.dart`、`base64url.dart` 与 68 项测试
（Flutter 测试总数 358 → 426）。
详见[运行汇总](../testing/evidence/2026-09-20/t03-01-01/summary.md)。

`lib/core/security/` 目录由此建立（`AGENTS.md` §4 目录规则要求该层存在）。

**最重要的一条不变量做成结构性而非约定性**：§2 要求「必须在发送令牌、HTTP 请求及文件内容之前
完成指纹比对」。这种规则很容易写下来、也很容易写错，因为**写错的实现仍然能与诚实服务端正常工作**。
所以令牌不是一个字段，而是只能经 `PairingHandshake.pairingToken` 取得，
该 getter 在比对成功前抛 `PAIR_REJECTED`——调用方没有顺序需要记住。

**指纹的三种「形状相同但语义不同」的写法**（DER / PEM 文本 / SPKI）都有测试固定差异，
因为弄错会得到一个看似合理却永远匹配不上的 pin。
