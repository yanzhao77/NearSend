# T12-07 接收流程与空间预检

状态：**待验证**
依赖：T12-02、T12-03
依据：`docs/ui/UI_UX_SPEC.md` §4–§6；`lib/core/storage/space_plan.dart`

## 目标

重做接收列表、接收确认、保存位置和空间明细。

## 退出门槛

- [x] `sufficient`、`insufficient`、`unknown` 分别表达。
- [x] unknown 不显示绿色通过。
- [x] known insufficient 阻止接受并给出下一步。
- [x] 保存位置使用平台句柄/URI，不强制转换为普通路径。
- [x] 多个待接收 offer 按 `transferId` 分别保存空间预检结果。

## 当前实现

- 接收列表、保存位置、目录选择、逐卷空间明细和风险确认已接入共享组件。
- 客户端 offer 与本机被推送 offer 均使用“接收并保存”；缺少保存位置、空间不足或空间未知未确认时不提供可执行接受动作。
- `ServerReceivingFlow.estimateFor()` 使用同一空间计划生成无副作用预检，实际接受仍重新计算并持久化空间估计。
- `ServerOffer` 当前没有对端设备名称、平台或地址字段，页面保持“未提供”而不猜测。
