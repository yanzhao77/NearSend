## 目标

建立接收方的持久化层：schema 与迁移框架、committed 块的唯一权威记录、durable checkpoint 事务、
恢复租约的获取与失效，以及高版本 schema 拒绝写入。使「断点续传只信 committed 块」这条核心规则
有一个可测试的实现，而不是靠调用方自觉。

## 范围内

- **schema 与版本**：`schema_version` 单一权威；表 `tasks`、`files`、`chunks`、`peers`、
  `idempotency`、`exports`，字段取自 `SYSTEM_ARCHITECTURE.md` §8。
- **迁移框架**：单调递增版本、逐版本迁移函数、升级前一致性备份（使用 SQLite backup API，
  而非复制活跃 WAL 的主文件）、迁移失败回滚并保留旧数据。
- **高版本拒绝写入**：数据库 schema 版本高于本构建时**拒绝打开写入**，不尝试修改。
- **chunk repository**：
  - `(file_id, index)` 唯一；`chunks.state` 区分未提交与 committed。
  - `commitChunkAfterSync`：**只有**在调用方已确认 durable sync 之后才允许提交块；
    repository 不替调用方决定顺序，但接口形状要让错误顺序难以表达。
  - committed 块是恢复的唯一权威；提供「列出缺失块」的查询，且该查询不得读取任何进度字节数。
- **恢复租约**：`acquireResumeLease` 提升 `lease_epoch`；`assertLease` 在每次写入前校验；
  旧世代写入被拒绝。复用 T02-02 的 `LeaseGuard` 语义，不重复实现规则。
- **幂等记录持久化**：与效果在**同一事务**中提交，使记录与效果不会分叉；
  复用 T02-02 的 `IdempotencyStore` 规则。
- **故障注入测试**（见「必做测试」）。

## 接口与不变量

- **committed 块是恢复的唯一权威。** `receivedBytes`/`writtenBytes`/UI 进度**不得**参与恢复决策；
  repository 不提供这类字段的读取接口用于恢复。
- 提交顺序由调用方保证为 `写入 → 块哈希校验 → durable sync → 事务提交 → 确认`；
  接口必须使「未 sync 就 commit」在类型或前置校验上难以发生。
- 同一文件同一时刻只有一个写入者；写入前校验 `lease_epoch`。
- 迁移失败必须回滚且旧数据可读；**不得**留下半迁移状态。
- 高于本构建的 schema 版本 → 拒绝写入，且不得修改数据库。
- 恢复凭证、密钥、令牌**不得**写入普通 SQLite 字段（`AGENTS.md` §5）；只存验证摘要或引用。

## 本次结果

### `t04-01-02`：schema、迁移与 chunk repository

已实现 `storage_schema.dart`、`storage_failure.dart`、`storage_migrations.dart`、
`near_send_database.dart`、`chunk_repository.dart` 与 38 项测试（Flutter 测试总数 168 → 201）。
详见[运行汇总](../testing/evidence/2026-09-20/t04-01-02/summary.md)。

**期间修复**：`writeBackup` 原先在 `try` 之外创建备份目录，目标不可写时抛出的是原始
`PathExistsException` 而不是 `StorageException(backupFailed)` —— 调用方唯一需要处理的失败条件
却拿到未类型化异常。已修复并由测试固定。

### `t04-01-03`：幂等持久化

已实现 `idempotency_repository.dart` 与 13 项测试（Flutter 测试总数 201 → 214）。
规则复用 T02-02 的定义，本文件只负责持久化。核心保证是**记录与效果在同一事务提交**，
并以「效果写入标记行 + 断言标记行与记录同时存在/同时回滚」直接验证，而不是只断言返回值。
详见[运行汇总](../testing/evidence/2026-09-20/t04-01-03/summary.md)。

### `t04-01-04`：任务/文件状态、导出记录与 peer 授权

已实现 `transfer_repository.dart`、`peer_repository.dart` 与 22 项测试
（Flutter 测试总数 214 → 236；存储测试 51 → 73）。
详见[运行汇总](../testing/evidence/2026-09-20/t04-01-04/summary.md)。

三条不变量由代码而非调用方保证：状态迁移只能在 T02-02 状态机的已定义边上发生；
导出只在文件全部 committed 后才能记录，且同一文件不会静默产生第二份副本；
peer 指纹变化只**报告**不吸收，只有用户的显式授权才改变已存信任。

**期间修复**：`NearSendDatabase.transaction` 把非 `StorageException` 的失败一律包装成
`NS-STORAGE-*`，导致状态机抛出的 `ProtocolViolation`（未定义的状态迁移）到达调用方时
被报告为「磁盘失败」。按错误码做重试决策的调用方会据此误判。已改为原样重抛
`ProtocolViolation`；该缺陷由本次新增测试发现。

## 必做测试

覆盖 `QUALITY_AND_ACCEPTANCE.md` §3「存储与恢复」矩阵：

| 场景 | 期望 |
| --- | --- |
| 块写入前崩溃 | 无 committed 记录，缺失块查询包含该块 |
| 写入中崩溃（部分字节） | 同上；不得出现长度不符的 committed |
| durable sync 前崩溃 | 不得提交；块仍为缺失 |
| sync 后、DB 提交前崩溃 | 不得出现 committed；重传后一致 |
| DB 提交后崩溃 | 块为 committed，恢复不需重传 |
| 磁盘满 | 提交失败且不产生 committed；保留可恢复状态 |
| DB 提交失败 | 不确认该块；状态可重试 |
| 暂存文件损坏 | 恢复/终检识别为损坏块，退回缺失 |
| 暂存文件丢失 | 同上，不得静默跳过 |
| 旧 lease 写入 | 拒绝 |
| 重复请求（同 request_id） | 返回同一结果，不重复写入 |
| 重新打开数据库（模拟重启） | 断点与 committed 块保持一致，不依赖内存状态 |

**本任务使用进程内故障注入与真实 SQLite 文件**；**断电**、真实磁盘满与平台 `syncData` 结论属 B04，
不得用本任务的结果代替。
