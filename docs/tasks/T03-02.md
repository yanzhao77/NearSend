## 目标

让一个真实文件从 Android 经同一局域网（无互联网、无云中转）流式传输到 Windows，
Windows 分块落盘并在整文件校验通过后导出到用户选择的目录，
两端 UI 显示真实的进度、速度、剩余时间与最终结果。

这是 T03 的退出门槛「用户授权后端到端收发」的落地，也是产品承诺的最小可验证形态。

## 范围内

- **传输层**：TLS 1.3 最低版本的 HTTPS/1.1 服务端与客户端；`/v1` 路由接真实 socket；
  §8 的帧定界规则（单一 `Content-Length`、拒绝 `Transfer-Encoding`、拒绝压缩、
  body 长度必须等于块预期长度）。
- **TLS 身份**：服务端自签叶证书 + 私钥，私钥只进入平台安全存储；
  二维码携带 `SHA-256(叶证书完整 DER)`；客户端对**每一个**证书比对 pin，
  包括本会被系统 CA 信任的证书；比对失败关闭连接且不发送任何令牌或 HTTP 请求。
- **端点补齐**（端到端所需子集）：`POST /pair`、`GET /offers`、`POST /transfers`（已实现）、
  `PUT /manifest`（已实现）、`POST /seal`（已实现）、`POST /decision`、
  `GET /authorization`、`POST /authorization/receipt`、`POST /resume`、
  `GET /status`、`PUT .../chunks/{index}`、`POST /checkpoint`、`POST /complete`、`POST /cancel`。
- **接收端（Windows）**：二维码/配对信息展示、接收确认与空间预检、按冻结清单分块落盘、
  checkpoint 持久化、整文件 SHA-256 终检、导出到用户选择的目录。
- **发送端（Android）**：SAF 选择真实文件、扫码、pin 校验与配对、清单与分块摘要计算、
  分批上传 manifest 页与 seal、流式分块上传（有界缓冲 + 背压，禁止整文件读入内存）。
- **两端 UI**：准备/传输/终检/导出阶段区分，真实进度、速度、剩余时间，成功与失败结果。

## 接口与不变量

1. **pin 先于令牌**：`PairingHandshake.pairingToken` 在指纹比对成功前抛 `PAIR_REJECTED`；
   比对失败的连接不发送 HTTP 请求、不发送令牌；每连接隔离。
2. **禁止整文件读入内存**：发送端按块从文件流读取；接收端按块写入暂存；
   任何路径都不得构造等于文件大小的缓冲区。内存上限须由测试或证据固定。
3. **committed 块是恢复唯一权威**：`receivedBytes`/`writtenBytes` 不得作为进度依据；
   checkpoint 与块标志同事务提交。
4. **完成 = 全部块 committed + 整文件长度/摘要正确 + 导出已确认**，三者缺一不可；
   终检失败不得进入 `COMPLETED`。
5. **不误删已导出文件**：`ExportSink` 端口不得出现删除/覆盖目标条目的方法。
6. **空间判定 `unknown ≠ sufficient`**：读数缺失时拒绝开始，不当作通过。
7. **状态转换单一编解码边界**：线上用 `TransferState`/`wireName`，SQLite 用 `StorageStateCodec`，
   业务代码不手写任一侧字符串。

## 必做测试

- 传输层：帧定界负例（双 `Content-Length`、`Transfer-Encoding`、压缩、长度不符）
- 安全：错误指纹拒绝且**不发任何请求**、CA 可信证书仍须比对 pin、过期/重复令牌、
  越权方向、任务取消后授权撤销、日志无令牌/密钥
- 存储：块中断、checkpoint 前后崩溃、设备重启、磁盘已满、源文件变化、旧世代被拒绝
- 内存：大文件传输期间峰值 RSS 有界（记录数值）
- 协议：固定测试向量（空文件、尾块、Unicode 文件名、>4 GiB 偏移、重复/缺失块、非法输入）
- UI：准备/空间不足/终检/导出各阶段文案与真实状态一致
- 真机：记录机型、系统、网卡、频段、距离、角色与结果
