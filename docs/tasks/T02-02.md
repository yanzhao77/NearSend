## 目标

把协议草案里以散文描述的状态机、错误模型、版本/能力协商、超时重试、`request_id` 幂等与
`lease_epoch` 规则收敛成 Dart 中**可测试的唯一实现**，并把草案中**没有定义**的部分显式登记为
冻结阻塞项，而不是自行补全。

这是「申请冻结协议 v1」的前置条件：冻结意味着这些规则不再有歧义。

## 范围内

- 完整错误模型：§11 的每个错误码带上 HTTP 状态、是否可重试、安全的用户文案键；
  实例级再带 scope（task/file/chunk/platform）、诊断上下文与 cause。§7 的错误体含 `retryable`，
  因此「是否可重试」是线上契约的一部分，必须逐码固定。
- 版本与能力协商：主版本不一致即拒绝；次版本仅在双方**共有能力**覆盖任务所需能力时继续。
- 任务状态机与文件状态机：状态集合与迁移表按 §10 与架构 §7。
- 超时与重试：连接/TLS 10s、控制请求 30s、块传输「30s 无进展」、重连 1/2/4/8s 递增加抖动、
  上限 30s、前台约 2 分钟后等待用户。
- `request_id` 幂等：作用域＝任务＋操作＋当前恢复凭证；同 ID 不同参数 → `REQUEST_ID_CONFLICT`；
  在途返回 202；同一恢复 ID 重试不得再次升代。
- `lease_epoch`：单调递增、恢复先撤销旧会话并等待旧写入停止后再分配新世代、旧世代写入 → `STALE_LEASE`。

- HTTP 服务器与路由实现（T03-01）。

- 能力词表的**具体取值**：草案未定义，本任务不发明（见下）。

## 接口与不变量

- 错误码只定义一处；`httpStatus`、`retryable`、`messageKey` 与码一一对应。
- 不得把原生异常原文当协议错误码；`message` 不含密钥与完整本地路径（§7）。
- 状态迁移必须由明确事件触发；未在 §10 定义的迁移不得自行添加。
- 同一任务同时只有一个有效写入世代；旧世代写入必须被拒绝。
- 同一恢复 `request_id` 重试不得再次递增 `lease_epoch`。
- 重连退避有上限；**禁止后台无限重试**（架构 §6）。
- 错误体中的 `retryable` 取值必须来自错误码，而不是调用方临时判断。

## 本任务发现的草案缺口（登记，不自行补全）

1. **能力词表未定义。** §3 的 `capabilities:[...]` 是占位；§17.1 要求「双方共有能力覆盖任务需求」，
   但没有定义任何能力标识。本任务实现**协商算法**并对能力标识做结构化校验，
   但**不发明词表**；词表必须在冻结前由维护者确定。测试用合成标识验证算法。
2. **BLOCKED / FAILED / PARTIALLY_COMPLETED 没有出边。** §10 只说明如何进入这些状态，
   没有说明如何离开（用户修复空间后从 BLOCKED 回到哪个状态？FAILED 可否重试？
   PARTIALLY_COMPLETED 如何继续未完成项？）。本任务只实现 §10 明确写出的迁移，
   未定义的出边一律拒绝并在台账登记。
3. **`CANCELLED` 之后的状态查询凭证与清理语义**在 §10 只写了「已完成任务的清理是另一操作」，
   未定义清理本身的状态；不作为本任务范围，登记备查。
