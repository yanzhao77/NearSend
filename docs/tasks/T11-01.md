# T11-01 MVP 双向数据面（Android ↔ Windows）

状态：进行中（见 [项目台账](../PROJECT_LEDGER.md) §4）。
分支：`feat/mvp-bidirectional-transfer`。
依据：`docs/protocol/v1.0-draft1.md` §6–§10、`docs/decisions/ADR-0004-staging持久化与恢复权威.md`、`AGENTS.md` §2/§5。

## 1. 目标

把「控制面」推进到「可以真实传输文件字节的最小闭环」：两端各自能作为发送方和接收方，
用真实 HTTPS 连接、真实 TLS pin、真实 SQLite checkpoint 传完一个文件的全部字节，并在接收端
落盘、整文件校验、导出。

## 2. 范围

本批**必须**完成（否则不得声称互传）：

1. manifest staging 落 SQLite，未 seal 可续传、已 seal 重启后可读（ADR-0004 的生产门槛）。
2. `POST /decision`、`GET /authorization`、`POST /authorization/receipt`、`POST /resume`，
   含空间预检、保存位置、`leaseEpoch`、`checkpointSeq`。
3. `PUT`/`GET` chunk 数据面，含 §8 的帧定界、长度、世代与摘要校验、批量 checkpoint 窗口。
4. `offers`、manifest 读取、`status`、`checkpoint`、`complete`、`pause`、`cancel`、`control`。
5. 本地文件层：分块暂存（每个块一个 part 文件）、流式读取发送、整文件校验、导出组装。
6. 两侧 UI 业务装配与真实进度显示。
7. 真机 + Windows 双向端到端验证（长度与 SHA-256 一致）。

## 3. 不在本批范围

- 热点（LocalOnlyHotspot）路径、Android 指定 Network 绑定：仍属 B01/B02。
- iOS：B06。
- 正式签名与发布：T10。
- mDNS 发现：协议 §3 的二维码/手动导入是必备入口，mDNS 为优先项，本批不做。

## 4. 验收条件

| 编号 | 条件 | 证据要求 |
| --- | --- | --- |
| 1 | schema 新库与升级库列完全一致，v6 可达 | 迁移测试 |
| 2 | 未 seal staging 重启后可继续补页；已 seal 清单重启后可读 | 注册表测试（真实 reopen） |
| 3 | 相同页重传幂等、重叠且内容不同被拒 | 注册表测试 |
| 4 | seal 与任务状态迁移、幂等结果同事务 | 端点测试断言任务仍为 `staging` |
| 5 | 未接受前不处理任何文件字节 | 端点测试断言拒绝时块数为 0 |
| 6 | 空间不足返回 `507 SPACE_INSUFFICIENT` 且不写批准行 | 端点测试 |
| 7 | 恢复凭证只以摘要入库，明文不入普通字段 | 测试断言凭证明文不出现在 `task_credentials` |
| 8 | 旧 `leaseEpoch` 写入失败 | chunk 测试断言 `STALE_LEASE` 且块仍 `missing` |
| 9 | `syncData` 成功后才提交；`verified_pending` 不计入已提交 | chunk 测试断言已提交数为 0 |
| 10 | 块长度/摘要/清单不符被拒 | chunk 测试 |
| 11 | 整文件长度与 SHA-256 一致后才算完成 | 终检测试 + 端到端 |
| 12 | 真机 Android 与 Windows 双向传完真实文件 | 见台账（**未完成**） |
