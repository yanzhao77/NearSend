## 目标

在 Dart 中**独立实现**协议 v1.0 的清单规范化与摘要编码（`LFTM1` 与 `LFTC1`），
并与 `docs/protocol/vectors-v1.json` 的固定向量逐字节比对一致，使协议不再只有 Python 参考实现。

## 范围内

- `lib/core/protocol/`：大端定宽写入器、§4 的十进制字符串/整数/UUID/摘要校验、
  §5.1 的相对路径词法规则、`LFTM1` 清单编码与摘要、`LFTC1` 块清单编码与摘要。
- 与 `docs/protocol/vectors-v1.json` 的固定向量比对（空文件、Unicode 路径、尾块）。
- 正反例覆盖：空文件、尾块、超过 4 GiB 的偏移与 20 GiB 规模、Unicode、
  JSON 字段顺序与空白不影响摘要而数组顺序影响、重复/缺失/乱序块、各类非法输入。
- 必要的加密原语依赖（`crypto`）按端侧设计 §12 评估并记录为 ADR-0002。

## 范围外

- 状态机、完整错误模型与版本协商（T02-02）。本任务只定义编码器需要的最小错误码子集。
- 网络传输、HTTP 路由、配对、令牌（T03-01）。
- SQLite 与 checkpoint（T04-01）。
- 文件读写与流式哈希调度（T04-01/T03-02）；本任务只实现摘要原语，不读取用户文件。
- 协议冻结：本任务通过固定向量**不**等于协议已冻结。协议冻结在其后另行申请。

## 接口与不变量

- 摘要只对规范二进制序列计算；**不得**对 JSON 文本求摘要（§5.2）。
- 整数一律定宽无符号大端；不得依赖语言默认序列化或本机字节序。
- 路径长度按 **UTF-8 字节数**计算，不按字符数或 UTF-16 码元数（§5.1/§5.2）。
- 块长度与偏移只由文件大小和索引推导，**不接受对端声明的偏移**（§8）。
- 只有最后一块可以短于逻辑块大小（§5.3）。
- 未知字段拒绝，不静默丢弃（§4）。
- 清单摘要不包含自身：`manifestDigest` 是外层字段（§5）。
- 编码器不读取用户文件、不访问网络、不持有凭证。

- [x] 证明摘要取自二进制编码而非 JSON 文本。
- [x] JSON 键序/空白不影响摘要；数组重排影响摘要。

### 首轮 CI 失败与修复（本任务的第二个产出）

第一次 CI 运行因证据文档中一个层级写错的相对链接而失败。本地检查曾报告通过，
但只覆盖已跟踪文件，而当时新文档尚未 `git add`——**这是同一类问题第二次把坏链接送进 CI**。
除修正链接外，`check_links.py` 增加 `--strict` 并在 `check.ps1` 中启用，
结论行也带上覆盖范围说明，使「通过」不再可能不覆盖工作区。首次失败记录原样保留。

## 已知缺口（登记而非隐藏）

协议 §5.1 要求接收端拒绝**非 NFC** 的相对路径。检测非 NFC 需要 Unicode 规范化数据，
Dart SDK 不提供。选择实现属于依赖决策，`AGENTS.md` §3 禁止凭偏好定案，因此本任务：

- **不**实现该拒绝逻辑；
- 在 `RelativePathRules.enforcesNfcNormalisation` 中以显式常量与注释暴露该缺口；
- 在测试中断言该常量为 `false`，使缺口无法被静默遗忘；
- 在 `docs/PROJECT_LEDGER.md` §5 登记为待人工决策项。

这不属于 T02-01 的退出门槛，但必须在协议冻结前解决。
