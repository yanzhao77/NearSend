# NearSend 连接交互重构开发方案

版本：1.0

日期：2026-09-30

适用项目：[yanzhao77/NearSend](https://github.com/yanzhao77/NearSend)

核对基线：`master` 提交 `64a2582cfab137a1735d0e8f07cecbebff253095`，GitHub 预览版 v0.1.17

文档性质：已确认的产品交互方案与开发验收要求。代码实施与自动化结果见[实施记录](../testing/evidence/2026-09-30/connection-ux/summary.md)；本方案本身不是设备验收证明。

## 1. 产品决定与交付目标

移除日常操作中的混合“连接信息页面”。本机二维码、发现设备配对、连接进度、已连接设备管理和高级手动连接分别承担单一职责，不再全部进入 `ConnectionPage`。

普通用户的路径应为：打开本机二维码供对方扫描，或扫描对方二维码；连接成功回到首页，在已连接设备中确认状态，然后进入传输。用户不需要理解 JSON、TLS 指纹、令牌或连接表单。

本次必须一起完成入口替换、旧路由清理、连接状态统一、异步操作收尾和相关测试。仅隐藏页面标题、删除输入框或把旧页面改名，不算完成。

交付目标：

1. 首页常规操作不再弹出旧“连接信息”页面。
2. 扫码取消、无效二维码、权限拒绝和连接失败都能稳定返回首页，显示一次清楚的反馈。
3. 点击已连接设备只出现设备操作卡片，可正确断开所选连接。
4. 点击发现设备明确进入配对流程；当前未认证设备仍通过二维码验证，不承诺无条件一键直连。
5. 传输任务由应用层管理，打开或关闭连接界面不意外结束任务。
6. 高级手动粘贴与桌面图片导入能力保留；普通入口不再经过高级页面。

## 2. 当前代码事实与问题定位

本节结论来自上述固定提交的代码；实施前必须重新读取最新主干，核对差异。

| 位置 | 已核对事实 | 本次处理 |
| --- | --- | --- |
| `lib/app/app.dart` | 定义 `connectRoute = '/connect'`；`_scanFromHome()` 先 push 该路由并传入 `scanArgument` | 首页扫码直接进入专用扫描器，再交给连接协调器 |
| `lib/app/app.dart` | `/connect` 路由根据扫描、发送、接收、RadarDevice 等参数组装同一个 `ConnectionPage` | 拆分用途，移除字符串参数对页面行为的混合控制 |
| `lib/features/transfer/presentation/transfer_pages.dart` | `ConnectionPage` 同时承载本机载荷、输入表单、扫描、图片导入、对端信息、连接反馈和断开按钮 | 提取可复用非页面能力后移除混合页面 |
| `lib/app/app.dart` | 未就绪且非 `qr-in:` / `qr-out:` 的发现项点击进入 `_scanFromHome()` | 改为配对引导与独立扫码，明确当前仍须二维码 |
| `lib/app/app.dart` | `_disconnectRadarDevice()` 根据 `qr-in:`、`qr-out:` 字符串前缀分派操作 | 迁移为类型化连接引用；过渡映射集中在适配层 |
| `lib/app/app.dart` | 出站二维码设备的 `isReady` 依赖 `peer.isConnected`、最近探测及 30 秒新鲜度 | 分离已配对、会话状态与最近可达性；灯灭不能自动变成未配对 |
| `lib/app/peer_session.dart` | 有出站会话 `disconnect()` | 保留并由统一断开用例调用 |
| `lib/core/security/pairing_service.dart` | PR #81 增加选定入站会话的撤销方法 | 保留按会话撤销；验证传输中断行为 |

已发现的是结构性风险，不等于已证明所有弹页现象只有一个根因。实施时还要排查首页本机设备、发现项、发送无连接提示、接收入口、返回栈、异步回调与测试代码中的所有旧跳转。

PR #81 修复了部分交互，但没有解除页面与多类连接状态之间的耦合。本次应替换结构，避免继续在同一页面上累加条件。

## 3. 范围与边界

优先交付 Android + Windows。共享 UI 在 macOS/Linux 保持可构建，按已有能力显示可用入口；iOS 不因共享界面存在就宣称已支持全部功能。

包含：页面拆分、路由迁移、统一连接操作、状态映射、取消与失败收尾、任务中断提示、回归验证、文档同步。

本次不引入新的配对协议、不实现 PAKE、不扩展 Windows 自动入网、不加入云中转，也不把 BLE 当作文件传输通道。已有热点 bootstrap 可以复用，但当前未验收能力仍须如实标记。

默认不修改数据库 schema、传输协议或依赖版本。确有必要时先明确理由、兼容性与迁移测试，不能为了 UI 重构顺手更换安全机制。

## 4. 新交互与入口映射

| 入口/情景 | 新行为 | 结束位置 |
| --- | --- | --- |
| 首页点击本机设备 | 打开“我的连接二维码”，只显示本机名称、二维码和简短说明 | 关闭后回首页 |
| 首页“扫一扫连接设备” | 检查权限并直接打开扫描器；拿到有效载荷后显示连接进度 | 成功或失败回首页 |
| 点击未认证 Wi-Fi 发现项 | 显示配对引导，说明需扫描对方二维码，提供“扫码配对” | 扫描与连接结束后回首页 |
| 点击未认证 BLE 发现项 | 显示配对引导，说明蓝牙用于发现，文件仍需要本地 Wi-Fi 链路 | 同上 |
| 点击当前可用的已连接设备 | 显示“设备连接”操作卡片，展示名称、状态和断开按钮 | 关闭/断开后留在首页 |
| 点击曾配对但当前离线/未知的设备 | 显示离线/待确认状态，可“检查连接”或“重新扫码配对” | 不把探测结果直接当作新授权 |
| 发送时没有可用连接 | 显示“请先连接设备”，可去首页扫码；不打开旧表单 | 回首页，连接后由用户重新进入发送 |
| 设置 → 高级连接 | 手动粘贴二维码内容；Windows 另提供二维码图片导入 | 成功返回首页 |
| Windows 首页“导入二维码” | 直接打开系统图片选择器，严格解析后连接 | 成功或失败留在首页 |

发现项点击先显示一个简短配对引导，是为了说明下一步需要什么。它不能展示原始连接 JSON，也不能再次包裹旧 `ConnectionPage`。直接“扫一扫”入口不经过该引导。

发现项携带的名称和地址不构成可信身份。若用户在扫描器中扫到另一个设备，连接应以实际二维码身份为准；不能沿用被点击候选的名称并冒充已验证身份。尚无可信设备名时显示“已扫码设备”。

### 4.1 我的连接二维码

标题：“我的连接二维码”。主体包括本机设备名、可用二维码、“让对方打开 NearSend 扫描此二维码”。使用现有安全载荷生成与生命周期，不在 UI 内自行拼令牌或指纹。

启动中显示真实加载状态；节点不可用显示原因和重试。刷新调用现有安全刷新用例，不能凭 UI 定时器重建身份或破坏既有会话。二维码失效、节点停止或邀请被消费后的行为与现有协议保持一致。

关闭二维码只关闭展示界面，不撤销已建立连接、不停止节点、不取消传输。打开页面不自动更换二维码。禁止保存或记录完整载荷到日志、截图测试基线或普通持久化字段。

### 4.2 扫码与连接进度

扫描器负责权限、摄像头、获取一个载荷、严格解析和返回结果，不负责跳转到发送/接收页面。建议结果为类型化的成功、用户取消、权限问题、解析失败与扫描器故障。

取得有效载荷后停止相机，关闭扫描器，再显示一个专用“正在连接”模态反馈。首页保留底部导航，模态结束后仍在首页。不得让旧表单在扫描器关闭时短暂露出。

成功时首页更新连接设备，显示一次“设备已连接”；不再额外弹连接成功页面。失败时显示一个带具体原因的对话框，可重试或关闭。用户取消扫描安静返回。

连接进度依据真实阶段显示：“正在加入本地网络”“正在验证设备身份”“正在建立连接”。只有经过真实握手并确认授权成功后，才能显示“设备已连接”。不支持的阶段不伪造执行动画或进度百分比。

建议连接反馈提供取消操作。取消后使该尝试失效，关闭尝试拥有的相机、网络 lease 和新建会话；晚到的成功必须清理，不能重新弹页或点亮设备灯。不能关闭此前已建立、与本次尝试无关的会话。

### 4.3 已连接设备操作卡片

Android 使用底部弹层，Windows 使用等价紧凑对话框。显示设备名称、已验证身份状态、当前连接状态、相关活动任务数量和“断开连接”。无需展示原始令牌、指纹或连接表单；“配对历史”与“当前连接”分开表达。

打开卡片与关闭卡片均不得修改授权或断开会话。卡片监听选定连接的真实状态；连接消失时改为“连接已断开”，禁用旧断开操作，不因 Listenable 更新重复弹卡片。

没有活动任务时直接执行断开。有活动任务时提示：“该设备有 N 个传输任务。断开会中断传输，已接收数据会保留；是否可继续以任务状态为准。”提供“继续传输”和“断开连接”。不能承诺尚未验收的自动续传能力。

断开选定入站会话时撤销其会话授权；出站会话关闭相应客户端。清理首页在线证明与应用持有的连接引用。与该连接相关的任务依据实际协议进入 interrupted/失败等合法状态，保留已提交 checkpoint 和已导出文件；不得把“断开”实现为删除任务或删除接收文件。

断开是会话操作，不等于忘记历史设备身份。先确定任务绑定关系，再中断相关任务；不能一律影响另一设备的会话。

### 4.4 高级连接

位置：设置 → 高级连接。标题：“高级连接”，简短提示：“用于无法扫码时连接设备”。包含手动粘贴输入、格式校验、连接按钮，以及有真实实现的平台二维码图片导入入口。

粘贴和图片导入与扫码调用同一个解析器及连接协调器，保持 TLS pin、一次性令牌、载荷大小/版本检查。不得因这是高级页面而允许跳过验证。

原始连接信息只在用户主动进入该入口时出现。高级页面不展示本机二维码、不兼作设备状态页、不自动跳到传输页。连接成功清空输入并返回首页；失败结束进度反馈后在高级页显示一次原因，保留可修正的输入；关闭清空内存输入。

## 5. 连接状态：统一依据，分清含义

不能只用 `isReady` 判断下一步应“扫码”还是“断开”。应分别维护发现候选、已授权身份、活动会话和最近可达性，再生成 UI 读模型。

建议使用以下语义；名称可适配现有代码，不要求生硬复制。

| UI 状态 | 真实依据 | 可用操作 |
| --- | --- | --- |
| 发现，未配对 | 只有 mDNS/BLE 广告，无已验证授权 | 扫码配对 |
| 正在配对 | 当前协调器有一次在途尝试 | 取消 |
| 已连接，待确认可达 | 已建立授权会话，但最近探测过期或结果未知 | 检查连接、断开 |
| 已连接且当前可用 | 授权会话有效，并有协议要求的新鲜认证/可达证据 | 传输、断开 |
| 历史设备离线 | 有历史授权记录，没有可用会话 | 检查连接、重新配对 |
| 已断开 | 会话已撤销/关闭，任务已得到正确收尾 | 重新配对 |
| 本次配对失败 | 当前尝试的结构化错误 | 重试/关闭 |

绿色呼吸灯只表示当前有可靠的新鲜在线依据。30 秒证明过期可让灯灭或状态改为待确认，不能单凭此事清空历史授权或自动唤起扫码页面。

设备项增加明确类型或连接引用，例如发现候选、入站会话、出站会话、历史身份。可以通过封闭类型或枚举实现。`qr-in:` / `qr-out:` 如仍用于现有存储或适配，在一个适配位置转换，业务页面不再到处解析字符串前缀。

扫描成功、握手成功、连接可达、准备发送、对端保存成功是不同事件；不得相互替代。连接状态模型与传输任务状态模型继续分离。

## 6. 应用层协调与异步收尾

建议新增或扩展 `PairingCoordinator`，统一以下职责：取得载荷后验证、调用已有网络 bootstrap、调用 TLS/令牌配对、映射错误、登记会话、取消和资源清理。它不包含 Flutter 页面代码，也不复制协议实现。

建议暴露类型化操作：`connectFromPayload(...)`、`cancelAttempt(...)`、`disconnect(connectionRef)`、`checkConnection(connectionRef)`，以及只读的操作状态。页面只发出意图和消费状态。

每次配对使用独立 attempt ID / generation。完成回调必须验证尝试仍有效、尚未取消且对应当前请求；过期结果不能更新设备列表或执行导航。同一时刻默认只允许一个交互式配对尝试，重复点击复用正在进行的反馈，不生成多份路由和握手。

涉及 Navigator 的操作必须有显式所有者与路由结果。不得盲目 `pop()` 以关闭“可能还在”的弹框；先确认对应路由仍存在。不得通过反复 `popUntil` 误清传输详情或其它任务页面。页面 dispose 后不调用 setState，不以 build/Listenable 回调无条件 push 新页面。

资源所有权：

| 资源 | 所有者 | 释放条件 |
| --- | --- | --- |
| 相机控制器/权限等待 | 扫描入口 | 获得载荷、取消、失败或生命周期暂停 |
| 本次连接 attempt | 协调器 | 成功移交会话；取消/失败则结束 |
| 本次新建网络 lease | bootstrap / 协调器 | 失败/取消释放；成功后移交连接生命周期 |
| 已建立会话 | 应用层会话管理 | 显式断开、会话失效或应用按既有策略停止 |
| 发送/接收任务 flow | 应用层任务管理 | 终态或明确取消；不由弹层 dispose 决定 |
| QR 展示 | 二维码页面 | 关闭停止页面监听，载荷仍由节点管理 |

初期可以只整理现有 App / PeerSession / NodeSession 的装配，不必引入庞大框架。关键是连接用例只实现一次，展示界面不再驱动业务对象生死。

## 7. 路由迁移与旧页面退场

建议新界面：

| 界面 | 建议路径/组件 | 是否承载配对业务 |
| --- | --- | --- |
| 我的连接二维码 | `/pairing/my-qr` / `LocalQrPage` | 只展示已有邀请 |
| 独立扫描器 | `/pairing/scan` / 现有扫描器组件 | 返回解析结果 |
| 正在连接 | `PairingProgressDialog` | 观察协调器 |
| 设备操作 | `ConnectedDeviceSheet` | 调用检查/断开用例 |
| 高级连接 | `/settings/advanced-connection` | 取得载荷，调用同一协调器 |
| 未配对设备引导 | `PairingGuideSheet` | 展示下一步动作 |

以上路径与名称为设计建议。实施前检查已有扫描器、二维码、图片导入组件，优先复用其安全解析与平台生命周期。

迁移顺序：先抽出非页面能力和新入口，再逐一替换旧调用，最后删除旧 `ConnectionPage` 与无用参数/常量。`transfer_pages.dart` 还可能包含共享模型和其它页面，禁止为了删除 ConnectionPage 删除整个文件。

搜索范围至少覆盖 `connectRoute`、`'/connect'`、`ConnectionPage`、`scanArgument`、`receiveArgument`、`PairingScanFailure`、`onRadarDevicePressed`、`pushNamed`、旧“连接信息”文案与相关测试。

内部路由若没有外部深链/持久化兼容需求，删除 `/connect` 注册。若确有已确认的兼容需求，可短期保留一次明确重定向：进入高级连接或首页；不能再渲染旧页面，也不能根据模糊参数猜用户意图。记录重定向原因和后续移除条件。

最终普通入口不得引用高级连接路由。已有发送/接收无连接逻辑分别提示用户回首页连接，不能再次将它们接到万能页面。

| MT-04 | 扫码取消、拒绝权限、无效码、过期码各重复 | 返回栈正确，错误一次性展示，下一次正常扫码可用 |

| MT-06 | 静置超过在线证明窗口再点击设备 | 显示真实状态；不会因灯灭自动重新扫码或丢失授权 |

| MT-08 | 传输中关设备卡片，再主动断开 | 关卡片不影响任务；显式断开中断相关任务并保留数据 |
| MT-09 | 中断后按已有任务能力重新接收/恢复 | 不崩溃、不露旧页；若恢复未实现明确记录，不能只测新任务替代续传 |
| MT-10 | Windows 导入 Android 二维码，Android 扫 Windows 码 | 两种入口都回首页；双向各传一个合成文件并核对哈希 |

## 11. 错误文案与可访问性

建议文案：权限拒绝为“需要相机权限才能扫描二维码”，永久拒绝提供系统设置入口；载荷过期为“二维码已失效，请让对方刷新后重试”；身份不匹配为“设备身份验证失败，请重新扫描对方二维码”；网络不可达为“无法连接设备，请检查两台设备的本地网络”；不支持自动入网时明确提示系统 Wi-Fi 操作。

错误分类来自实际平台/协议错误，不把所有异常都替换成“连接失败”。技术诊断可使用无敏感信息的错误码，用户主界面不要展示堆栈、JSON 或未经处理的平台句柄。

按钮有明确语义标签；二维码提供设备名与文本说明；状态不能只靠绿色；200% 字体、窄屏和长设备名不溢出。Windows 支持键盘、Esc 关闭和焦点返回原入口；Android 返回键按当前层级取消或关闭，不能退出错页。

## 12. 完成标准与文档同步

只有以下条件满足，才可标记“连接交互重构完成”：

1. 本机设备、首页扫码、发现设备、已连接设备与无连接发送入口全部按新映射运行。
2. 常规路径没有旧连接表单；旧页面/路由/参数已清理或有明确兼容重定向说明。
3. 取消、失败、重复点击和晚到结果的回归通过，资源所有权清楚。
4. TLS 指纹及一次性令牌安全边界保持；断开只影响目标连接。
5. 格式、分析、全量测试和 Android/Windows 构建通过。
6. Android 双机与 Android/Windows 关键手工矩阵有记录；缺设备时只标“代码与自动化完成，设备验收未完成”。
7. README、`docs/PROJECT_LEDGER.md` 与 `docs/releases/1.2/ACCEPTANCE.md` 同步真实状态。

基线仓库文档仍把 v0.1.14 写成最新版本，而真实发布已经是 v0.1.17。交付时应使用当时实际最新版本和 CI/Release 链接，不继续复制这两个旧版本号。当前版本摘要和历史快照分别标识，保留历史失败记录。

本次涉及安全配对与撤销、网络 lease 清理、任务中断的部分需重点审阅。不得删除失败测试、放宽身份验证、重置数据库、伪造完成状态或通过卸载应用掩盖状态残留。

发布仍按预览版口径：本次页面重构不解决 Android debug signing、macOS 签名或全部设备能力验收。成功构建和生成安装包不能代替稳定版验收。
