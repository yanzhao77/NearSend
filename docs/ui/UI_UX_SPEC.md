# NearSend UI/UX 与视觉规范

> 视觉交付入口：[UI 设计交付](README.md) · [样式指南](STYLE_GUIDE.md) · [移动端核心流程](mockups/mobile-core-flow.svg) · [Windows 传输页](mockups/windows-transfer.svg)

状态：MVP 实施基线。视觉值可在品牌设计后微调，但关键状态、信息层级和安全文案不得删除。

## 1. 体验原则

1. 让用户始终知道正在做什么、为什么需要等待、是否可以离开。
2. 区分准备、网络传输、校验和保存，不用一个 0–100% 进度掩盖阶段。
3. 先解释风险再请求系统权限；不诱导用户开启与当前动作无关的权限。
4. 错误必须给出下一步；不显示“未知错误，请重试”作为唯一信息。
5. “完成”只表示文件已校验并保存到目标位置。
6. Windows 与移动端保持同一信息架构，同时尊重键鼠、窗口和系统控件习惯。

## 2. 信息架构

| 一级入口 | 内容 |
| --- | --- |
| 首页 | 本机二维码、已配对设备、Wi-Fi 与蓝牙发现、继续任务 |
| 传输 | 发送文件、接收文件 |
| 任务 | 活动、暂停、可恢复和近期完成任务 |
| 空间 | 未完成任务占用、暂存保留期、可安全清理项 |
| 设置 | 设备名、接收目录、隐私、安全、诊断、关于 |

移动端使用底部导航时5 个一级项：首页、传输、任务、空间、设置；Windows 可使用左侧 NavigationRail。首次版本若功能不足，可将空间和设置放入二级页面，但不能隐藏活动任务。

## 3. 核心用户旅程

### 发送

传输页“发送文件” → 文件选择 → 准备/扫描 → 选择连接方式 → 配对 → 等待对方确认 → 传输详情 → 校验/保存 → 结果。

### 接收

传输页“接收文件” → 同网发现/扫码/创建离线连接 → 验证设备 → 查看清单和空间 → 选择保存位置并接受 → 传输详情 → 结果。

### 恢复

首页/任务“继续” → 重新连接设备 → 本地恢复校验 → 缺失块传输 → 终检 → 保存/结果。

## 4. 页面规格

### 首页

- 本机设备卡可点击，打开本机二维码页面；可刷新一次性二维码。
- 本机设备下始终展示已配对设备栏，未配对时显示引导；扫码确认后自动显示本次会话设备。
- 已连接设备行末显示绿色呼吸灯，同时显示文字状态；关闭系统动画时显示静态绿点。
- 扫码会话状态独立于 Wi-Fi/蓝牙发现开关；发现列表与独立开关保留。
- 发送文件与接收文件移到独立“传输”页，继续使用现有安全传输流程。
- 次操作：继续任务，仅在存在可恢复任务时显示数量和最近一项。
- 状态：本机设备名、当前网络可用性；不把“有 Wi-Fi”表述为“已联网”。
- 空态用一句话解释“无需互联网，设备之间仍需建立本地 Wi-Fi 连接”。

### 文件选择与准备

- 显示已选数量、可获得时的总大小、来源异常。
- 开始扫描后文案：“正在准备文件：已扫描 X / Y。准备完成后开始传输。”
- 单个大文件显示读取/哈希字节进度；小文件集合显示数量进度。
- 提供取消；剩余时间只在采样稳定后显示。
- 云端占位文件离线不可读时，明确要求用户先下载，不无限重试。

### 连接与配对

- 入口：附近设备、扫码连接、创建离线连接、手动连接帮助。
- 附近设备只标为“发现”，在完成指纹验证前不使用“可信”。
- 展示双方设备名、平台、指纹短码/视觉校验和确认动作。
- 二维码过期、网络切换、指纹变化需显示安全原因并重新开始。
- 系统即将弹出热点/Wi-Fi/本地网络确认前，先展示解释页。

### 接收确认

- 应用处于前台时，无论当前页面是什么，收到新的发送清单都由应用级收件提醒弹出文件名、大小和总量，并提供“接收／拒绝”；同一时间最多一个模态框。后台系统通知不在本版范围内。
- 选择“接收”后进入逐次确认，用户仍需确认保存位置、文件名和空间信息；这一步之前不得授权文件内容传输。选择“拒绝”则撤销本次任务授权。
- 展示发送设备、文件数、总大小、类型摘要和完整清单入口。
- 展示目标位置、预计暂存、导出峰值、余量与总新增需求。
- 按存储卷分别显示；空间未知时使用警告：“无法确认此位置的可用空间，传输中仍可能失败。”
- 主要按钮写“接收并保存”，不只写“确定”。
- 文件名冲突策略在开始前可见：询问/自动重命名/跳过；MVP 默认自动安全重命名。

### 传输详情

- 顶部显示任务总体状态和对端设备。
- 阶段条：准备、连接、传输、校验、保存；已完成、当前、未开始清晰区分。
- 网络阶段展示速度、已传/总量和文件数；不要把校验耗时计入网络速度。
- 文件列表展示每文件状态，支持筛选失败项；一万文件时虚拟化。
- 操作：暂停/继续、取消、后台说明。取消二次确认并说明已保存文件不会删除。
- 恢复时使用：“正在检查已接收内容，检查通过的部分无需重新传输。”
- 网络断开时显示自动重试倒计时和“立即重连”；超过上限转为可恢复暂停。

### 结果

- 成功：文件数、总大小、保存位置、端到端耗时；提供打开位置和完成。
- 部分成功：成功/失败/跳过数量，失败原因分组，“仅重试失败项”。
- 保存失败：明确数据已验证但尚未导出（若事实如此），提供更换位置并重试。
- 完整性失败不得使用绿色成功样式；保留可诊断信息和安全重试路径。

### 空间管理

- 列出活动/暂停/过期任务的实际占用、可恢复性和最后活动时间。
- 清理前说明会失去哪些恢复数据；已导出文件不在清理范围。
- 批量清理只默认选择可安全删除的过期临时数据。

## 5. 视觉基础

### 色彩 Token

| Token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `primary` | `#2563EB` | `#60A5FA` | 主操作、当前阶段 |
| `onPrimary` | `#FFFFFF` | `#0B1220` | 主色上的文字 |
| `surface` | `#FFFFFF` | `#111827` | 页面/卡片 |
| `surfaceAlt` | `#F1F5F9` | `#1F2937` | 次级分区 |
| `textPrimary` | `#0F172A` | `#F8FAFC` | 主要文字 |
| `textSecondary` | `#475569` | `#CBD5E1` | 辅助文字 |
| `success` | `#15803D` | `#4ADE80` | 已校验并保存 |
| `warning` | `#B45309` | `#FBBF24` | 空间未知、可恢复风险 |
| `error` | `#B91C1C` | `#F87171` | 安全、完整性、不可完成 |

颜色不是唯一状态信号；始终配合图标、标题或文字。所有前景/背景组合需达到 WCAG AA 对比度，实际实现用自动测试或审计工具确认。

### 字体与间距

- 使用平台系统字体；正文 14–16sp，关键进度 24–32sp，最小辅助文字不低于 12sp。
- 4px 基础网格：4/8/12/16/24/32。
- 触控目标至少 48×48dp；Windows 紧凑控件也要有可见焦点与足够点击区。
- 内容最大宽度：表单/确认约 720px，任务详情约 1080px，宽屏避免无限拉伸。

### 形状与动效

- 卡片圆角 12，按钮 10，进度条端点圆润；边框优先于重阴影。
- 状态切换 150–250ms；传输进度平滑但不能伪造增长。
- 尊重系统“减少动态效果”；长时间扫描使用确定/不确定进度的真实组合。

## 6. 核心组件

| 组件 | 必要状态 |
| --- | --- |
| Primary/Secondary/Danger Button | default、hover、focus、pressed、disabled、loading |
| Device Card | discovered、verifying、trusted、unreachable、fingerprint-changed |
| File Row | queued、preparing、transferring、verifying、saving、done、failed、skipped |
| Stage Progress | complete、active、pending、blocked |
| Space Breakdown | sufficient、insufficient、unknown、changed |
| Error Banner | retryable、action-required、security-stop |
| Permission Explainer | rationale、system-denied、settings-required |
| Task Card | active、paused、recoverable、partial、completed、expired |

组件 API 接收领域枚举和格式化数据，不接收任意颜色或自由异常字符串。

## 7. 文案规则

- 使用动作和结果：“重新连接”“更换保存位置”“仅重试失败项”。
- 不使用虚假保证：“绝对安全”“永不失败”“已完成”但仍在导出。
- 技术细节分层：主文案说明影响，详情页展示错误码与诊断 ID。
- 文件大小使用统一二进制单位（KiB/MiB/GiB）或统一产品决定，不同页面不得混用。
- 权限拒绝说明缺失功能，不威胁或诱导用户。

推荐错误结构：

```text
标题：空间不足，传输已暂停
说明：还需要约 3.2 GiB 才能完成暂存和保存。已接收且校验通过的内容会保留。
主操作：管理空间
次操作：更换位置
详情：NS-STORAGE-003 · 诊断 ID xxxx
```

## 8. 响应式与平台差异

- 手机为单栏逐步流程；平板/桌面可使用清单 + 详情双栏。
- Windows 支持拖放作为选择文件的快捷入口，但文件选择器始终可用。
- 桌面支持键盘 Tab、Enter、Escape 和上下文菜单；危险操作不能只在右键菜单出现。
- 二维码在 Windows 端可大尺寸显示，并提供地址/配对材料的辅助复制，但复制内容标记敏感和短时有效。
- iOS/Android 系统权限、分享入口和后台限制使用平台原生文案习惯。

## 9. 可访问性与隐私

- 屏幕阅读器能读出阶段、数值和错误，不每个进度 tick 高频播报。
- 进度条提供语义值；未知总量读为“正在扫描”，不读 0%。
- 支持动态字体至至少 200%，关键按钮和状态不被截断。
- 截图/最近任务预览中尽可能隐藏二维码和完整敏感文件名。
- 日志复制前提示用户预览和移除敏感信息。

## 10. UI 验收清单

- 准备大文件时有真实扫描进度和取消。
- 接收前显示完整空间需求明细，未知空间不冒充充足。
- 恢复时明确展示本地校验阶段。
- 暂停、网络中断、应用重启、磁盘满、部分失败均有对应状态和下一动作。
- 完成只在终检与导出提交后出现。
- 手机和 Windows 常见窗口尺寸无溢出；键盘、屏幕阅读器、深色模式可用。
- 10,000 文件列表滚动与进度更新不会明显卡住 UI。
