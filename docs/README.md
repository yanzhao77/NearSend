## 文档权威级别

发生冲突时按以下优先级处理：

1. `AGENTS.md` 的安全、完整性和工程红线。
2. 已确认的产品范围与协议版本规范。
3. 架构决策记录（后续放入 `docs/decisions/`）。
4. 架构、端侧、UI 和测试实施规格。
5. 任务卡与台账中的执行信息。
6. 代码注释、Issue、PR 说明和聊天讨论。

如果高优先级文档自身冲突，停止相关实现，在台账登记阻塞并提交 ADR 或文档修订，不能由 Agent 私自选择一种解释。

## 从文档到代码的追踪链

每个开发项必须形成以下闭环：

`需求/约束 → 设计章节 → 任务 ID → 分支/PR → 自动测试与真机证据 → 台账状态`

任务没有退出门槛不能开始；没有可核对证据不能标记完成。文档完成仅表示设计基线存在，不表示产品功能已实现。

## 变更规则

- 功能变更先更新对应规格或在同一 PR 中同步更新。
- 协议字段、状态机、错误码、数据库 schema、空间算法与安全规则变化必须单独说明兼容性。
- 图示只解释关系；表格中的不变量、接口和验收条件才是实现约束。
- 版本、依赖、最低系统要求在目标设备验证前保持“待冻结”，不得把候选项写成事实。
- 每次合并后更新 `PROJECT_LEDGER.md`；只有实际结果才改变状态。
