# NearSend Agent 任务手册

## 1. 使用方式

维护者从 `PROJECT_LEDGER.md` 选择一个已就绪任务，为 Agent 提供任务卡。Agent 开始前必须阅读 `AGENTS.md`、本手册、任务引用的设计和协议章节。没有清晰退出门槛时先补卡，不直接编码。

## 2. 标准任务卡

```markdown
# <任务ID> <标题>

- 基线分支/SHA：
- 负责人或 Agent：
- 状态：就绪
- 依赖：
- 关联规格：
- 风险级别：普通 / 协议 / 安全 / 存储 / 迁移 / 删除

## 目标
用一两句话描述用户或系统获得的可验证结果。

## 范围内
- ...

## 范围外
- ...

## 接口与不变量
- ...

## 验收条件
- [ ] ...

## 必做测试
- ...

## 交付物
- 代码/文档/测试/证据路径

## 台账回填
- 更新任务状态、证据、阻塞、下一动作
```

## 3. Agent 开工提示词模板

```text
你负责 NearSend 的 <任务ID>。先读取 AGENTS.md、docs/AGENT_TASK_PLAYBOOK.md 及任务卡列出的规格。
只实现范围内内容，不降低安全、完整性、空间或恢复要求。
先给出受影响文件、实施步骤、风险和验证计划；确认仓库当前状态后再修改。
完成后执行任务要求的检查，审阅 diff，并更新 PROJECT_LEDGER.md。
最终报告：修改、实际测试、未测试原因、风险、人工复核点和下一步。
```

任务卡应直接提交到 GitHub Issue 或 `docs/tasks/`（二选一后保持统一），不要只存在聊天中。

## 4. Agent 工作步骤

1. 探索：确认基线、现有实现、相关测试和未解决冲突。
2. 规划：拆为可逐步验证的改动，列出协议/schema/UI 影响。
3. 实现：小步提交；每个提交保持可构建或明确为同一原子提交的一部分。
4. 验证：运行适用测试，保留真实输出；失败不删除测试。
5. 自审：检查越权、边界、错误路径、日志、资源释放和无关 diff。
6. 交接：更新台账，创建 PR，写清未覆盖环境与剩余风险。

## 5. 文件所有权建议

并行期为冲突高发区指定临时所有者：

| 范围 | 单一所有者职责 |
| --- | --- |
| `core/protocol` + `docs/protocol` | 字段、编码、版本、向量 |
| `core/storage` + schema/migrations | checkpoint、迁移、导出事务 |
| `core/security` | pin、令牌、凭证、授权 |
| `ui` + Design Token | 组件 API、主题、关键状态文案 |
| 各平台目录 | 系统 API 与资源生命周期适配 |

所有者不是唯一编码者，而是合并与一致性责任人。跨所有权变更必须在任务卡中列出。

## 6. 审查清单

### 通用

- 是否严格对应任务卡，没有偷偷扩大范围？
- 错误和取消路径是否释放网络、文件、锁和订阅？
- 是否新增无依据依赖、重复模型或魔法常量？
- 用户可观察状态是否与持久化事实一致？

### 协议与安全

- pin 是否先于凭证提交？请求是否验证任务、方向、范围和世代？
- 是否处理重放、重复、未知字段和版本不兼容？
- 日志/测试快照是否泄露令牌、密钥或完整敏感清单？

### 存储与恢复

- 是否遵守 write → hash → durable sync → DB commit → ack？
- 恢复是否只信 committed 块？旧 lease 是否拒绝？
- 导出和清理是否可能误删、覆盖或重复？

### UI

- 准备、恢复校验、传输、终检和保存是否区分？
- 空间 unknown/insufficient 是否正确表达？
- 部分失败、重试、后台和可访问性是否覆盖？

## 7. 台账回填模板

```markdown
| <ID> | <成果/任务> | 待验证/阻塞/已完成 | <PR、测试、证据链接> | <限制和下一步> |
```

状态改变时补一条更新记录。仅文档完成写“已完成：设计”；只有目标端退出门槛通过才能写产品能力“已完成”。

## 8. 建议的首批任务顺序

1. `T01-01` 创建 Flutter 工程与 Android/Windows 最小启动。
2. `T01-02` 建立 format/analyze/test/build CI 和版本信息注入。
3. `T02-01` Dart canonical manifest 与固定向量。
4. `T02-02` 协议状态/错误码/版本协商模型。
5. `B01/B02` Android 热点、Network 绑定和 TLS 探针。
6. `T04-01` SQLite schema、迁移框架与 durable chunk repository。
7. `T03-01` 同网二维码配对与单文件最小链路。
8. `T06-01` 空间计划、终检与导出闭环。

其中 B01/B02 可与 Dart 纯模型工作并行；单文件链路依赖协议模型和存储提交顺序，不宜提前做成不可恢复 demo。

## 9. 禁止的“提速”方式

- 为演示关闭证书校验、摘要或 durable sync。
- 用内存进度冒充重启后的恢复依据。
- Agent 自己宣布平台能力通过却没有设备记录。
- 一个 PR 同时重写架构、替换依赖并实现多个里程碑。
- 先生成所有页面静态壳，再把没有后端状态的按钮标记完成。
- 用聊天消息或截图替代 Git 中的规范、测试和台账。
