# Wi-Fi 与蓝牙设备入口实现说明

## Source

- 用户需求：将首页统一的“附近设备雷达”拆成 Wi-Fi 局域网连接和蓝牙连接两个入口。
- 设计基线：`docs/ui/STYLE_GUIDE.md`、`docs/ui/UI_UX_SPEC.md`。
- 提取日期：2026-09-24。

## Scope

- 首页提供两个独立开关、状态说明和设备列表。
- Wi-Fi 区块只展示 mDNS 局域网候选；蓝牙区块只展示 BLE 候选。
- 两个列表都优先展示发现来源真实提供的设备名称。
- 点击任一设备进入所选对端的安全连接页。
- 已配对历史不冒充当前 Wi-Fi 或蓝牙发现结果。
- 不改变 TLS 指纹、一次性令牌和实时身份验证要求。

## Layout

- 保留首页发送、接收和继续任务区域。
- 原雷达位置改为“Wi-Fi 局域网连接”区块。
- 蓝牙区块紧随 Wi-Fi 区块，区块间距使用 `NearSendSpacing.lg`。
- 每个区块使用无外层卡片的纵向结构：开关、运行/错误文案、设备列表。
- 设备使用 `ListTile`，设备名为标题，平台/发现状态为副标题，右侧使用进入图标。
- 手机保持单栏；桌面沿用首页最大内容宽度，不创建额外双栏。

## Visual Style

- 使用现有 Material 3 主题、系统字体、语义颜色和间距 Token。
- Wi-Fi 使用 `wifi_outlined`，蓝牙使用 `bluetooth`，不依赖颜色区分来源。
- 只有经过实时身份验证且就绪的设备显示绿色状态标记。
- 未认证候选不显示成功色，不使用“可信”文案。

## Components And States

- 两个入口分别支持：关闭、启动中、已开启、关闭中、错误。
- 开关忙碌时禁用，状态文案说明当前实际动作。
- 空列表不制造示例设备；入口开启后显示对应诚实空态。
- 设备名缺失时显示“未命名设备”或“未命名蓝牙设备”，不得用地址伪装名称。
- 长设备名最多显示两行并省略，动态字体 200% 时不与图标或副标题重叠。

## Interactions

- Wi-Fi 开关仅启停 mDNS 发布和浏览。
- 蓝牙开关仅请求蓝牙授权并启停 BLE 广告、扫描和控制会话。
- 应用进入后台时分别关闭两个入口并释放各自资源。
- 点击设备将完整 `RadarDevice` 传入连接路由，连接页展示所选对端。
- 候选信息不能直接授予信任；需要继续完成现有安全配对。

## Assets

- 无新增图片资产；使用 Flutter Material 图标。

## Open Questions

- Windows BLE 插件不支持应用自定义广播名称；若扫描结果也没有系统名称，列表必须显示未命名，
  后续需要通过经过审查的 BLE 控制消息交换展示名，不能扩大广告载荷后假定所有适配器支持。
- 首次 PAKE 尚未冻结，因此点击未认证候选只能进入现有安全连接流程，不能静默建立可信连接。
